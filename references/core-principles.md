# 核心原则

## 触发即进入本 Skill 的工作方式

只要用户在策划、编写、优化以下内容，就必须默认进入本 skill 的流程：
- 各类课程的策划与制作。
- 职业辅导脚本。

## 八项核心原则

### 1. Plan 驱动与 Plan Agent
进入任务后，必须先调用 `enter_plan_mode`。对于复杂任务，应考虑调用 `plan agent` 细化步骤。

### 2. 先确认时长与规范，后开始内容
禁止在未确认"课程时长"和"命名规范示例"的情况下开始生产。时长是评估内容密度的核心标尺。

### 3. 多版本 L1-L4 分层同步
多版本管理遵循四层分层：
- **L1 产品体验 / L2 架构逻辑 / L3 工艺规范** → 必须一致
- **L4 技术实现** → 各自独立，不做类名/方法级 1:1 翻译映射
- 写各自技术栈最地道的实现，而不是另一栈的翻译腔
- 详见 `phases/phase-0-explore.md`（多版本识别）与 `phases/phase-4-sync.md`（L0-L4 对齐清单）

### 4. 工业案例新鲜度与调研通道
- 凡是引用工业案例（尤其是演进路线段），发布时间 ≤ 1.5 年，必须有量化指标和来源标注
- Phase 2 工业案例调研走**零依赖通道**：WebSearch 检索 + `curl -s "https://r.jina.ai/<URL>"` 取正文；通道定义与可选项见 `references/evolution-roadmap.md` §3.4
- 详见 references/evolution-roadmap.md §3

### 5. 过程文件隔离
禁止在课程正式目录下创建任何过程文件夹（如 `_process`）。所有过程产物（草稿与各阶段正式产出）必须统一存储在 `.course/` 下，按任务名隔离；课程目录只放正式交付物。

路径规则：
- 若有已选择的项目目录 → 项目根目录下的 `.course/{task_name}/phase-n/`
- 若无项目目录（仅临时工作区） → 当前工作目录下的 `.course/{task_name}/phase-n/`

### 6. 视角 A-I 评估门禁（共九个）
所有产出物必须通过 Phase 5 的**视角 A-I** 审查，不合格必须重做。**逐条判据的唯一出处是 `phases/phase-5-review.md` §2**，本文件只列索引、不复述判据：

| 视角 | 名称（课型适用见括号） |
|:---|:---|
| A | 流量运营与转化（公开课/录播课对应大纲；实战课对应讲义） |
| B | 讲师授课（对应讲义） |
| C | 学员学习（对应课程文档） |
| D | 深度技术架构（讲义 + 课程文档） |
| E | 演进路线专项（系列实战课必检） |
| F | 附录深入思考题专项（**F1-F10**，实战课必检） |
| G | 代码引用与飞书兼容专项（**G1-G10**，应用架构课必检） |
| H | 教学代码生产级门禁专项（**H1-H8**，实战课必检；含代码对照与接线核验） |

> 计数口径：早期写作"三视角"、扩章后写作"六视角"，加视角 I 后**实际为 A-I 共九个**——涉及视角数量时一律以此表为准。五项专项（E-I）的判据各有唯一定义：F 见 `references/interview-questions.md`，G 见 `references/code-reference-feishu.md` §8，H 见 `references/multi-track-production.md` §2，I 见 `references/executable-claims.md`；`phase-5-review.md` 只列编号清单，引用时须同时给出条目编号与文件位置。

### 7. 附录深入思考题质量门禁（实战课）
- 思考题质量判据（F1-F10）的唯一定义见 `references/interview-questions.md`（§2 三维度、§6.2 硬性规则、§7 反模式清单），本节不复述

### 8. 实战课·应用架构专项原则

八条原则（代码先行 / 引用零容错 / 演进叙事 / 量化驱动 / 评测闭环 / 架构决策）的**完整判据见 `references/architecture-course.md`**（§二 前置条件、§3.2 演进叙事五步法、§3.3 ADR、§5 量化与评测）与 `references/code-reference-feishu.md`（代码引用），本节不复述。

三条最容易走偏的底线单独强调：**讲义始终以最终可运行代码为准**——代码没写完、指标没达标就不写讲义，开发中架构有调整也等稳定后再改；**量化表必须三段式**（Baseline → 各阶段 → 最终），每项优化要挂得住"Precision@5 从 60% 到 90%"这种具体涨跌，不写"效果变好了"；**必须讲"什么时候不需要这个设计"**，否则等于教人过度设计（客服场景单 Agent 足够，就不必上 Multi-Agent）。

## 反绕开原则

以下行为被视为绕开本 skill，必须纠正：
- 在没有命名规范示例的情况下盲目创建目录。
- 在 Phase 0/1/2 未完成前直接跳到 Phase 3 写稿。
- 为多版本对齐而做类名/方法级 1:1 翻译映射。
- 多版本同步时强行对齐 L4 技术实现层。
- 将过程文件散落在课程目录中。
- 工业案例使用过期（>1.5年）数据或无来源量化指标。
- 演进路线起点档与主 Demo 代码不一致（套模板）。
- 未经视角 A-I 评估就宣称工作完成。
- 深入思考题违反质量判据（题库凑数/给标准答案/跳过候选题确认等）——判据唯一定义见 `references/interview-questions.md`。
- **实战课·应用架构特有反模式**：六条完整清单见 `references/anti-patterns.md`「应用架构类」（那是唯一定义，本节不复述）——含"代码未达标先写讲义""不读代码凭记忆虚构类名""只讲怎么做不讲 trade-off""无量化只写效果显著""把架构课讲成源码解读""过度设计"。

# 核心原则

## 触发即进入本 Skill 的工作方式

只要用户在策划、编写、优化以下内容，就必须默认进入本 skill 的流程：
- 各类课程的策划与制作。
- 职业辅导脚本。

## 七项核心原则

### 1. Plan 驱动与 Plan Agent
进入任务后，必须先调用 `enter_plan_mode`。对于复杂任务，应考虑调用 `plan agent` 细化步骤。

### 2. 先确认时长与规范，后开始内容
禁止在未确认"课程时长"和"命名规范示例"的情况下开始生产。时长是评估内容密度的核心标尺。

### 3. 多版本 L1-L4 分层同步
多版本管理遵循四层分层：
- **L1 产品体验 / L2 架构逻辑 / L3 工艺规范** → 必须一致
- **L4 技术实现** → 各自独立，不做类名/方法级 1:1 翻译映射
- 写各自技术栈最地道的实现，而不是另一栈的翻译腔
- 详见 SKILL.md §6 与 phases/phase-4-sync.md

### 4. 工业案例新鲜度与 agent-reach 调研
- 凡是引用工业案例（尤其是演进路线段），发布时间 ≤ 1.5 年，必须有量化指标和来源标注
- Phase 2 工业案例调研必须通过 agent-reach skill 执行，禁止用通用 WebSearch 替代
- 详见 references/evolution-roadmap.md §3

### 5. 过程文件隔离
禁止在课程正式目录下创建任何过程文件夹（如 `_process`）。所有过程产物（草稿与各阶段正式产出）必须统一存储在根目录 `.course/` 下，按任务名隔离；课程目录只放正式交付物。

### 6. 五视角评估门禁
所有产出物必须通过"流量运营"、"最终学员"、"代码质量"三视角审查 + 演进路线专项检查（系列实战课）+ 附录深入思考题专项检查（实战课）。不合格必须重做。

### 7. 附录深入思考题质量门禁（实战课）
- 实战课默认每讲附录 4 道深入思考题（3 架构题 + 1 深度题）
- 每道题必须通过三质量维度：考察知识结构而非记忆 > 紧扣本课但超纲 > 有 trade-off
- Phase 2 必须先产出 8-10 张候选题卡片，经用户人工确认选 4 道，禁止跳过直接写终稿
- 候选题检索必须通过 agent-reach（Exa 搜索 + Jina Reader），禁止用通用 WebSearch 搜"XX 面试题"凑八股
- 终稿只给答题骨架不给标准答案，每道题必须有至少 1 条工业界关联阅读
- 详见 references/interview-questions.md

## 反绕开原则

以下行为被视为绕开本 skill，必须纠正：
- 在没有命名规范示例的情况下盲目创建目录。
- 在 Phase 0/1/2 未完成前直接跳到 Phase 3 写稿。
- 用通用 WebSearch 代替 agent-reach 做工业案例调研或候选题检索。
- 为多版本对齐而做类名/方法级 1:1 翻译映射。
- 多版本同步时强行对齐 L4 技术实现层。
- 将过程文件散落在课程目录中。
- 工业案例使用过期（>1.5年）数据或无来源量化指标。
- 演进路线起点档与主 Demo 代码不一致（套模板）。
- 未经五视角评估就宣称工作完成。
- 附录深入思考题跳过候选题→人工确认关卡直接写终稿。
- 深入思考题用基础知识题/定义题凑数（如"什么是 XX"）。
- 深入思考题给完整标准答案而非答题骨架。

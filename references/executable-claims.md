# 讲义内容可执行性专项（I1-I5）

> **为什么单独有这一层**：`multi-track-production.md §2` 的 H1-H8 管的是**仓库代码**能不能编译、能不能跑、指标有没有基线；本专项管的是**讲义里写的那些东西**——给学员的命令、让学员自检的断言、贴出来的代码块、引用的数字、标题承诺的内容——在当前代码状态下是否成立。
>
> 两类缺口互不覆盖：代码是对的，讲义照样可以让学员跑不通。实测样本：某轮审查 10 份讲义查出 19 条阻断项，其中 12 条落在这里（H1-H8 全部通过，因为仓库代码确实没问题）。

适用：所有含代码与命令的课型（实战课必查；应用架构课、公开课若含命令也查）。

---

## I1 讲义给的命令可跑通

**判据**：讲义里出现的每条命令，在过去时态下能在**当前仓库状态**跑通，且不绕过仓库自带的入口脚本。

**怎么查**
1. 抽出讲义中所有命令块（`bash` / `shell` / 无标注但以 `pnpm` / `mvn` / `npm` / `node` / `git checkout` 开头的行）。
2. 对每条命令判断：它是仓库的**正式入口**（如 `scripts/run-eval.sh`、`pnpm --filter X start`）还是**手搓等价物**（如直接 `mvn exec:java`）。
3. 手搓等价物必须能说明"它绕过了什么"。若绕过的是 `.env` 装载、构建前置、陈旧制品门禁，判不合格——学员照抄会拿到静默降级的结果。

**反例（实测）**：讲义写 `mvn -q -pl lesson9-12-travel compile exec:java`，而仓库唯一入口是 `lesson9-12-travel/scripts/run-eval.sh`（脚本里显式 `source` 模块根 `.env` 并跑 `eval-stale-guard.sh`）。照抄讲义 ⇒ 无 key 静默兜底，指标全是假账。

**不合格怎么改**：换成正式入口；确需给底层命令时，在同一代码块里补前置（`source .env`）并注明"不要绕过脚本"。

---

## I2 断言与命令分支同源

**判据**：讲义让学员"看到 X 就算通过"时，X 必须是该命令**在该参数分支下**的真实返回值。

**怎么查**
1. 找到所有"末行应包含 / 输出应为 / 看到 X 说明"型断言。
2. 回到代码，找到该命令实际走的分支（`--fallback` / `--force` / `--mock` / 环境变量缺省）。
3. 逐字比对断言串与分支的返回字面量。**同一命令带不同开关会走不同分支，断言要跟着开关走。**

**反例（实测）**：讲义要求跑 `pnpm start -- --fallback "…"`，断言末行含 `fallback(未配置 LLM key)`。而 `BaseWorker.run` 第一条分支就是 `if (forceFallback) return { error: 'fallback(强制兜底)' }`——带 `--fallback` 时永远不可能出现"未配置 LLM key"。学员按讲义自检必然判失败。

**不合格怎么改**：二选一，并在任务卡里写清两条兜底分支的前缀不同——① 去掉开关，断言保持"未配置 key"；② 保留开关（若该分支本身是教学点），断言改"强制兜底"。**不要为了消掉矛盾而删掉那个被验证的分支。**

## I3 代码块可编译，或显式标注省略

**判据**：标注为"现场写"的代码块，学员照抄后必须能编译/运行；确实是节选的，块内或块后必须显式说明省略了什么。

**怎么查**
1. 找出标"【现场写】""本步骤新增代码""完整实现"的代码块。
2. 对照源文件确认：类/方法签名齐全、抽象方法全实现、被调用的私有方法在块内或前文出现过。
3. 注释占位（`/* 读三个 error 键拼 summary */`、`…`、`// 略`）一律视为不可编译，除非块外有一段"以下省略 X，完整实现见 Y"。

**反例（实测）**：某课 4.4 的任务是"现场写 `TravelGraph.java`"，代码块把两个节点体写成注释、`workerNode`/`transfer`/`req` 三个方法完全没出现；下一节却写"跑通后应看到 X"。学员照抄既编译不过，也跑不出承诺的输出。

**不合格怎么改**：从源文件复制补齐（可删注释、可加行内注释，**不得臆造方法名**）；若篇幅受限，只保留本步骤真正新增的方法，其余用一句"其余方法见仓库 X 文件，本步骤不涉及"收口，并把"跑一下"降级为"编译通过"。

## I4 数字与当前代码/口径文件一致（含时效）

**判据**：讲义里每个量化数字，都能追溯到**当前**代码常量或口径文件的**当前可引用段落**；曾被修正过的数字必须跟改。

**怎么查**
1. 列出全部数字（样本量、通过率、token、耗时、行数、文件数、条目数）。
2. 两个方向核对：
   - **横比**：数字 ↔ 代码常量（如 `EvalSampleSizes.MAP_ROUTE_SAMPLE_SIZE=20`）、单测实际输出。
   - **纵比**：数字 ↔ 口径文件（`METRICS*.md`）。**先看该段落有没有"已过期 / 仅历史对账 / 不得对外引用"的标记**，再看数值。
3. 同一指标出现在多课、多轨时，必须同值；双轨数值不同则必须写明分母差异（如"共享口径 100% / 离线自验 75%，分母含查无此人"）。

**反例（实测）**
- 样本量：代码已把单测循环从 21 次收口到 20 次（`210/210`），讲义仍写 `231/231`（旧口径）。
- 已证伪数字：口径文件明写"跨城 320min 超阈值"的根因**已被证伪**（实为时序✗，且已由 `clampDay` 消除），讲义仍把它当唯一量化锚点。
- 跨口径混算：单案归因 17,625 token 摆在"20 条全量 17,001"同一节里——17,625 是另一套模型口径的历史值。

**不合格怎么改**：能查到当前值就改；查不到就把数字降级为定性描述（"多数 case"）或标注"历史口径、不与本节混算"，**不许编**。

## I5 标题承诺有对应正文

**判据**：标题（`##`/`###`）里承诺的动作或结论，正文必须有对应段落兑现；否则改标题。

**怎么查**
1. 抽出全部标题，标出含动词/判断的（"先落到哪张表""为什么不该排队""三步跑通""谁读什么"）。
2. 对每个标题问：正文里哪一段回答了它？找不到 ⇒ 不合格。
3. 反向也查：正文里整段讲 A，而标题写 B ⇒ 改标题对齐正文（不要为了保标题而硬加内容）。

**反例（实测）**：某课标题与课时名都写"先落到哪张表"，全课没有一句讲表怎么定——正文只有一行 `?? DEFAULT_TABLE`，学员读完不知道屏幕上"选中表：sales_order"那行是谁写的。同期 3.1 的"三类信息"还漏了词表里真实存在的表黑话（`targetType='table'`）。

**不合格怎么改**：补一段最小兑现（谁定的、默认值是什么、什么情况会变），或在 3.1 的结构表里补一行；**如果这个承诺本来就超出本课范围，改标题**（改标题比硬撑一段更诚实）。

## 执行顺序（Phase 5）

1. `node scripts/course-lint.mjs scan <目录>` —— 机械项先清零（禁词 / ASCII 组图 / 占位标题 / 图片可达 / 围栏）。
2. `node scripts/course-lint.mjs structure <目录>` —— 讲义 ↔ 课程文档段数是否对齐（🟡 措辞差异可留，❌ 段数差异必须解释）。
3. 人工过 I1-I5。**每条结论都要给证据位置**（代码 `文件:行` 或口径文件 `/§`）——没有证据位置的断言，主审不予采纳。
4. 数字类（I4）优先于修辞类：一个错数字的杀伤力大于十处长句。

## 与既有视角的关系

| 既有 | 分工 |
|:---|:---|
| 视角 H / `multi-track-production §2`（H1-H8） | 仓库代码能不能跑、指标有没有基线 |
| **本专项 I1-I5** | 讲义里的命令、断言、代码块、数字、标题承诺能不能兑现 |
| 视角 G / `code-reference-feishu`（G1-G10） | 类名、路径、索引表与代码是否一致（"名字对不对"） |
| 视角 D（技术深度） | 技术判断是否成立（Ⅰ2/I5 查"断言与实现是否相反"） |

> 一句话区分：H 查**代码**，G 查**名字**，I 查**学员照着讲义做能不能成**。

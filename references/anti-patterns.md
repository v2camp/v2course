# 反模式清单

以下行为必须规避：

## 流程类
- 还没讨论清楚方向，就开始写大纲/讲义
- 用"先写草稿再改"绕开前期讨论
- 只做快速收敛，不做互相质疑
- 没有给出备选方向和不选理由
- 在 Phase 0/1/2 未完成前直接跳到 Phase 3 写稿

## 证据类
- 默认优先查互联网案例，而不是先问用户自己的经历
- 未先尝试 agent-reach 即默认走通用 WebSearch（降级本身允许，见 `SKILL.md` §3 快速路径与 `phase-2-cases.md` 调研通道；反模式是「不试就退」）
- 工业案例使用过期（>1.5年）数据或无来源量化指标
- 演进路线的失败模式套模板（不是基于本课主 Demo 实际短板推导）
- 演进路线起点档与主 Demo 代码不一致（硬套通用模板把已实现能力标为"未实现"）
- 把模糊经历写成确定性行业事实
- 主讲述线和事实支撑线混在一起，谁负责讲故事、谁负责证明不清楚

## 内容类
- 为了看起来完整，硬塞一个敷衍的行动清单
- 系列课没有桥接，导致每一讲像孤岛
- 演进路线跨课时 handoff 与前后课矛盾（本课说下节课讲 X，但下节课实际讲 Y）
- 讲义结构很完整，但没有真正的主张与张力
- 案例卡片表存在，但讲义正文没有真正使用这些证据
- 结尾为了"完整"牺牲了听众价值感

## 多版本同步类
- 为了"对齐"而做类名/方法级 1:1 翻译映射
- 强行对齐 L4 技术实现层，导致某一版本出现"翻译腔"代码
- 要求 TS 代码遵循 Java 的习惯或反之

## 附录深入思考题类（实战课）
- 思考题质量判据（F1-F10）与反模式清单的唯一定义见 `references/interview-questions.md`（§2 三维度、§6.2 硬性规则、§7 反模式清单），本节不复述

## 代码与配置类
- 演示代码改了，但讲义代码示例没同步更新
- 各产物（讲义/大纲/README 等）中引用了已废弃的服务名、API Key 或配置项

## 入门实战规格类（实战课·入门实战）
- 「预装、不现场装」：把可现场演示的构建环节全部预生成，学员只能看结果——入门实战课必须保留 3-4 个关键决策文件现场写（预置/现场写分界见 `templates.md §3.2`）
- 「全量代码索引当学员抓手」：用全工程类名/路径索引充当学员材料，而不是只列 basic 内文件的本课增量清单（文件/作用/为什么此刻引入）
- 「讲预生成完整工程目录」：按代码目录巡览讲既有工程，文件跳来跳去串联不起来；讲解主线必须是数据流/调用链，不是目录树
- starter 骨架缺完整类型契约或 mock 数据，导致学员不依赖 LLM key 就跑不起来
- 现场写变成现场抄：关键文件从头默写不给"为什么这么写"，或全是样板代码没有决策点
- **「组件学习塞附录」**：把本课必需的组件 / 设计模式放进「附录·按学员基础插讲」当可选项——正课不讲、基础弱的学员直接跳过，等于没有。必讲组件进段二，只有延展部分才进附录（三问筛选见 `hands-on-lesson.md §2.2`）
- **「组件说明书」**：枚举 API / 配置项代替讲解；组件学习须先给「没有它会翻什么车」的失败现场，再给组件，一项配一图
- **「课上念提示词」**：把现场构建四拍换成"念提示词让 AI 生成、学员看结果"——这正是「预装、不现场装」的新变体。harness 驱动只能放在课后任务卡
- **「任务卡无判据」**：完成判据写成"实现得差不多""基本可用"，或没有「不许改」清单——学员无法自检，harness 还会改崩 starter 契约
- **「任务与演进线无关」**：任务卡做成与 basic→full 演进无关的独立小玩具，学员做完的产物下一节架构课接不住（选题三问见 `hands-on-lesson.md §4.2.1`）
- **「提示词依赖课堂上下文」**：提示词里写"按刚才讲的做法""如上所述"，学员课后单看无法执行
- **「谎称已验证」**：任务卡标注「已实跑」但实际只做了静态推演——仓库既有红线，未实跑就如实写「静态推演」
- **「一图多义」**：把组件关系与执行流程塞进同一张图；三类保底图各司其职（见 `hands-on-lesson.md §2.4`）
- **「过渡契约悬空」**：入门课第六段预告的增强点，架构课没有对应锚点（或架构课凭空造了一个 basic 里不存在的痛点）；须两向勾稽（见 `hands-on-lesson.md §5`）

## 应用架构课专属
- 代码还没写完/指标还没达标就开始写讲义
- 不Read真实代码，凭设计稿/记忆虚构类名方法名
- 只讲"怎么做"不讲"为什么这么做、有什么trade-off"
- 没有量化指标对比，用"效果显著提升"等模糊表述
- 把架构课讲成"源码解读课"——逐行讲代码而非讲架构决策和演进
- 过度设计：把生产级方案直接灌给学员，不解释"什么时候不需要这么复杂"

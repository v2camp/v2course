## 流程类
- 用「先写草稿再改」绕开前期讨论（改的是措辞，不是方向）
- 其余流程红线（方向没定就写大纲 / 只收敛不互疑 / 未给备选与不选理由 / Phase 0-2 未完跳 Phase 3）见 `phase-0-explore.md` 必谈项、`phase-1-spine.md` 六问

## 证据类
- 默认优先查互联网，而不是先问用户自己的经历
- 未先尝试 agent-reach 即默认走通用 WebSearch（降级允许，反模式是「不试就退」；见 `SKILL.md` §3）
- 把模糊经历写成确定性行业事实
- 主讲述线与事实支撑线混在一起，分不清谁讲故事、谁证明
- 过期数据 / 失败模式套模板 / 起点档与代码不一致 → `evolution-roadmap.md` §3.1-3.2

## 内容类
- 为了"看起来完整"硬塞一个敷衍的行动清单
- 结构很完整，但没有真正的主张与张力
- 结尾为了"完整"牺牲听众价值感
- 系列课无桥接 / handoff 与前后课矛盾 / 案例囤而不用于正文 → `phase-2-cases.md`、`phase-3-produce.md`

- L0 独立与 L1-L3 对齐的边界 → `phase-4-sync.md`

## 入门实战规格类（实战课·入门实战）
- 「预装、不现场装」：构建环节全部预生成，学员只看结果——必须保留 3-4 个决策文件现场写（`templates.md §3.2`）
- 「全量代码索引当抓手」：用全工程类名/路径索引充材料，而非只列 basic 内增量清单
- 「讲预生成完整工程目录」：讲解主线应是数据流/调用链，不是目录树
- 「组件学习塞附录」：必讲组件进附录当可选项，等于没有
- 「组件说明书」：枚举 API 代替讲解；须先给"没有它会翻什么车"，一项配一图
- 「课上念提示词」：现场构建换成念提示词看结果——是「预装」的新变体；harness 只放课后任务卡
- 「谎称已验证」：标「已实跑」实际只做静态推演——未跑就写「静态推演」
- 「一图多义」：组件关系与执行流程塞进同一张图（三类图各司其职，见 `diagram-integration.md §6.1`）
- 「过渡契约悬空」：入门课预告的增强点，架构课没有对应锚点（两向勾稽见 `hands-on-lesson.md §5`）

## 应用架构课专属
- 代码还没写完/指标还没达标就开始写讲义
- 不 Read 真实代码，凭设计稿/记忆虚构类名方法名
- 只讲"怎么做"不讲"为什么这么做、有什么 trade-off"
- 没有量化指标对比，用"效果显著提升"等模糊表述
- 把架构课讲成"源码解读课"——逐行讲代码而非讲架构决策与演进
- 过度设计：生产级方案直接灌给学员，不解释"什么时候不需要这么复杂"

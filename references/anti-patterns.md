# 反模式清单

以下行为必须规避：

- 还没讨论清楚方向，就开始写大纲
- 用"先写草稿再改"绕开前期讨论
- 只做快速收敛，不做互相质疑
- 没有给出备选方向和不选理由
- 默认优先查互联网案例，而不是先问用户自己的经历
- 把模糊经历写成确定性行业事实
- 主讲述线和事实支撑线混在一起，谁负责讲故事、谁负责证明不清楚
- 为了看起来完整，硬塞一个敷衍的行动清单
- 系列课没有桥接，导致每一讲像孤岛
- 讲义结构很完整，但没有真正的主张与张力
- 案例卡片表存在，但讲义正文没有真正使用这些证据
- 结尾为了"完整"牺牲了听众价值感
- 演示代码改了，但讲义代码示例没同步更新
- 讲义/大纲/README 中引用了已废弃的服务名、API Key 或配置项

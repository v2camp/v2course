# 审查总表（多维度勾稽清单）

> 适用范围：审查/复核/重新审**已完成的课程产物**（讲义、课程文档，或两者）。定义于 SKILL.md §3 快速路径「审查/复核」条目。
>
> 铁律：动笔审查前，**先按 §2 课型矩阵加载该课型的完整必载 reference 清单**，再按本表逐维勾稽。禁止跳过必载清单、只凭单文档（如 quality-guide）做文体润色——那是本轮要修的既往缺口。

## 审查总原则

1. **多维度，不单看文体**：篇幅结构、逻辑、深度、架构、演进、措辞、引用、双端、代码九个维度必须逐维过一遍，不能只挑印象最深的。
2. **每个维度都必须勾稽到对应必载 reference**，以该 reference 的检查点为准，不是审查员个人口味。
3. **九维全过才算审查完成**；任一维度不合格，标记 🔴 并定位到 Phase 3 对应子阶段回改。
4. **产物级分轨**：讲义与课程文档分开审——同一维度对两份文档的落脚点不同（口语 vs 书面、讲师话术 vs 学员自读）。

## 讲义专项重点（与课程文档分轨）

- 去 AI 腔（禁用词：首先/其次/综上所述等已彻底清除）
- **情绪张力是否绝对基于真实案例，严禁凭空捏造**
- 三大卡片组件与浮夸词汇已清除；【要点】【知识点】【敲黑板】规范承载干货
- 无 ASCII 图，一切配图走 v2svg（IR 入库、同基名、回执通过）
- 【备课参考】每节 ≥2 篇，有来源、有价值说明、有发布日期
- 演进路线案例新鲜度 ≤1.5 年；起点档与主 Demo 一致
- 附录深入思考题 F1-F10 全勾（若有）
- 应用架构课：代码引用（G1-G10）+ 生产级门禁（H1-H8）+ **代码对照与接线核验**（`multi-track-production.md` §2.5）全勾

## 课程文档专项重点

- 去口语彻底（无"咱"、"大家"、"我们来看"）
- 去教学残留（无演示动作、无挖坑填坑、无互动提示）
- 去时间标记（基础/实战/公开课必检）：章节标题不得残留（15min）等地段时长
- 技术书面语质量：表达准确、专业、流畅
- 可独立阅读（不依赖讲课语境；应用架构课按"只有文档、没开仓库的学员"假设）
- 【延伸阅读】质量（应用架构课：案例入正文、出处留延伸阅读，一一对应）

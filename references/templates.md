# 标准交付模板

> 本模板定义 course-skill 三种重点产品(公开课、实战课、录播课)的差异化全链路交付规范。多版本仅实战课;本规范只针对未来新课,现有课程不回填/不迁移。

## 1. 产品定位与交付物清单

| 产品 | 定位 | course-skill 必产交付物 | 可选交付物 | 人工产物(不审计) |
|---|---|---|---|---|
| **公开课** | 认知破题、转化承接 | `选题&大纲.md`、`大纲.md`、`讲义.md` | `案例卡片表.md`、`演示脚本与观测面设计.md`、`images/`、`design/` | — |
| **实战课** | 技能习得、作品沉淀 | `大纲.md`、`讲义.md`、`images/` | 多版本(TS/Java)并行 | 案例代码仓库(外部) |
| **录播课** | 平台合作、口碑沉淀、持续收入 | `大纲.md`、`讲义.md`、`PPT文稿.md`、`录制脚本.md` | `images/`(PPT 用图) | `录制视频.mp4`、视频剪辑、`.pptx` 成品 |

**录播课章节时长约束:** 总时长 ≥1 小时(上限 8 小时),单章节 8–20 分钟(利于完播率,严于三节课"≤30min"上限)。

**PPT文稿.md** 是 course-skill 产出的 PPT 内容稿(含每页标题/要点/讲师口播/视觉建议),人工再套三节课 PPT 模板成 `.pptx`。

**录播课价值重心:** 通过头部平台露出获得持续收入的同时,积累专业影响力(口碑)。兼顾知识性、实用性、高效率、一点点情绪价值。平台分发核心指标:完播、点赞、收藏。

## 2. 目录与文件命名规范

| 产品 | 目录命名 | 文件命名 | 风格说明 |
|---|---|---|---|
| **公开课** | `courses/公开课/`(扁平,所有讲次共目录) | `第N讲：标题（产物）.md`,如 `第一讲：2026程序员生存指南（讲义）.md` | 保留中文冒号+括号风格(人可读,讲次为序) |
| **实战课** | `courses/实战课/AI-Agent-实战课-N-{TS\|Java} 版/` | `标题-大纲.md`、`标题-讲义.md` | 连字符风格,版本后缀隔离多版本 |
| **录播课** | `courses/录播课/{课程名}/`(新建) | `标题-{产物}.md`,如 `Agent入门-大纲.md`、`Agent入门-PPT文稿.md`、`Agent入门-录制脚本.md` | 连字符风格,无版本后缀 |

**设计取舍:** 不强行统一三种产品的命名风格——公开课的"第N讲"中文序号符合其按讲次连载的现实;实战课的版本后缀是多版本管理的必需;录播课无版本、按课程名组织。统一的是"产物类型后缀"语义(大纲/讲义/PPT文稿/录制脚本)。

**实战课多版本隔离:** 多版本(TS/Java)通过目录层隔离(`AI-Agent-实战课-N-TS 版/` vs `AI-Agent-实战课-N-Java 版/`),大纲内部不标多版本差异。同步由 phase-4 负责。

## 3. 核心产物内容结构骨架

### 3.1 公开课

**大纲.md** — 分分钟段时间轴(强转化)
```
# 第N讲:标题
## 0. 课程信息(时长/目标/主线/教学前提/代码示范原则)
## 1-N. 分段(每段含:时间区间 + 目标 + 讲什么 + 接地气举例 + 讲师动作)
   ├─ 必含:破题段 / 核心判断段 / 公开案例段 / 焦虑拆解段
   ├─ 必含:课程地图段(转化钩子,植入正课)
   └─ 必含:行动清单段 + 结论收口段
## 附录:案例来源链接(每条含 URL + 摘要 + 用于哪段)
```

**讲义.md** — 大纲的展开版,补口播逐字稿要点与互动设计。

**演示脚本与观测面设计.md**(可选) — live coding 步骤 + 观测面(日志/控制台/监控)设计。

### 3.2 实战课

**大纲.md** — 认知→案例→原理闭环
```
# 第N讲:标题
> 系列:AI Agent 实战培训(共X课时)/ 本讲:第N课时 / 时长
## 一、系列桥接/开场破题
## 二、核心判断(一句话主张 + 错误vs正确认知表 + 本讲解决/不解决)
## 三、认知模型/原理铺垫
## 四、主案例展开(多帧拆解表:帧/Agent行为/ReAct阶段/口播要点)
## 五、原理抽象(代码逐行/架构图)
## 六、能力全景图(三域地图等)
## 七、收口:行动清单
## 八、转化承接(后续课时handoff表 + 课程产品承接)
## 附录:关键来源(链接+类型)
```

**讲义.md** — 大纲展开 + 完整代码 + SVG 图引用(images/)。

### 3.3 录播课

**大纲.md** — 章节≤30min、按章节组织
```
# 课程名(总时长/章节数/目标受众/合作平台)
## 章节列表(每章含:序号+标题+时长8-20min+知识点+对应PPT页码区间+对应录制脚本段)
## 章节间衔接逻辑(上一章收尾→下一章钩子)
## 附录:参考来源
```

**讲义.md** — 大纲展开,每章节补:口播要点、演示动作、画面提示。

**PPT文稿.md** — 逐页稿
```
# 课程名-PPT文稿
## 第X章 标题
### P1 标题
- 要点(bullet)
- 讲师口播
- 视觉建议(图/图表/排版)
### P2 ...
```

**录制脚本.md** — 分镜表
```
# 课程名-录制脚本
## 第X章
| 分镜 | 画面 | 口播 | 时长 | PPT页 | 备注(出镜/屏幕操作) |
```

**设计取舍:** 公开课大纲强调"时间轴+转化段";实战课大纲强调"认知闭环+handoff";录播课大纲强调"章节切片+页码/脚本交叉引用"。讲义在三种产品里都是"大纲展开版",但录播课讲义额外补"画面提示"以服务录制。

## 4. 6 阶段按产品裁剪

phase 文件不动,差异在本表查。共享 6 阶段框架,各阶段产物按产品裁剪。

| 阶段 | 公开课 | 实战课 | 录播课 |
|---|---|---|---|
| **phase-0 探索** | 时长90min / 命名(第N讲) / 无多版本 / 破题定位 / 主案例 / 演示形态 | 时长 / 命名(版本后缀) / 多版本共性特性 / 习得定位 / 主案例 / live coding | 总时长+章节数 / 命名(课程名) / 无多版本 / 平台定位 / 主案例 / PPT+录制形态 |
| **phase-1 主线** | 破题→判断→案例→焦虑→课程地图→行动→收口 | 认知→案例→原理→全景→收口→handoff | 章节序列 + 衔接逻辑 |
| **phase-2 证据** | 公开案例证据卡 + 转化论据 | 技术案例证据卡 + 代码论据 | 知识点证据卡 + 演示论据 |
| **phase-3 生产** | 选题&大纲 / 大纲 / 讲义(+案例卡片表 / 演示脚本) | 大纲 / 讲义 / images | 大纲 / 讲义 / PPT文稿 / 录制脚本 / images |
| **phase-4 同步** | 跳过(无多版本) | TS/Java 双版本同步 + 代码对齐记录 | 跳过多版本;做 PPT↔脚本↔大纲交叉引用一致性 |
| **phase-5 评估** | 运营+学员(见 §5.2) | 运营+学员(见 §5.2) | 影响力/口碑 + 平台分发 + 平台合规(见 §5.2) |

**phase-4 关键差异:** 实战课是唯一有"多版本同步"负担的产品;录播课虽无多版本,但 PPT页码↔录制脚本分镜↔大纲章节 三向交叉引用需校对,作为 phase-4 录播课专属任务。

## 5. 两层评估体系

三种产品统一为"过程门禁(phase 0-4)+ 最终评估(phase-5)"两层结构。差异只在指标项,框架本身一致。

### 5.1 制作过程评估(phase 0-4,每阶段退出前门禁)

| 阶段 | 公开课 | 实战课 | 录播课 |
|---|---|---|---|
| **phase-0** | 时长(90min)合理性 [合格/不合格] / 破题角度适配 [1-5] / 主案例适配 [1-5] | 时长合理性 [合格/不合格] / 多版本共性特性划分清晰 [1-5] / 主案例适配 [1-5] | 总时长+章节数合理 [合格/不合格] / 章节切片(8-20min)规划 [合格/不合格] / 主案例适配 [1-5] |
| **phase-1** | 一句话主张锐度 [1-5] / 破题→判断→案例→焦虑→课程地图→行动→收口 主线完整 [1-5] / 转化边界清晰 [1-5] | 一句话主张锐度 [1-5] / 主线结构完整 [1-5] / 本讲解决·不解决边界清晰 [1-5] | 一句话主张锐度 [1-5] / 章节序列主线完整 [1-5] / 章节间衔接逻辑清晰 [1-5] |
| **phase-2** | 公开案例证据卡完整 [1-5] / 转化论据分工合理 [1-5] | 双轨证据卡完整 [1-5] / 论据分工合理 [1-5] | 知识点证据卡完整 [1-5] / 演示论据分工合理 [1-5] |
| **phase-3** | 初稿完成度 [1-5] / 分分钟段时间轴标注完整 [合格/不合格] / 转化段(课程地图)落地 [合格/不合格] / 去 AI 腔 [合格/不合格] | 初稿完成度 [1-5] / 代码可跑通 [合格/不合格] / SVG 规范 [合格/不合格] / 去 AI 腔 [合格/不合格] | 四产物(大纲/讲义/PPT文稿/录制脚本)完成度 [1-5] / 章节时长合规 [合格/不合格] / 去 AI 腔 [合格/不合格] |
| **phase-4** | 跳过多版本;若为系列,做讲次间承接校对 [1-5] | 多版本差异对齐 [1-5] / 代码对齐记录完整 [1-5] | PPT↔脚本↔大纲 交叉引用一致性 [1-5] |

### 5.2 最终产物评估(phase-5)

**公开课**
- 流量运营:标题张力 [1-5] / 痛点戳中 [1-5] / 转化钩子合理性 [1-5]
- 学员:时长匹配 [合格/不合格] / 行动清单可执行性 [1-5] / 转化承接自然度 [1-5]

**实战课**
- 流量运营:标题张力 [1-5] / 痛点戳中 [1-5] / 转化钩子合理性 [1-5]
- 学员:内容密度与时长匹配 [合格/不合格] / 步骤可复现性 [1-5] / 简历价值/获得感 [1-5]

**录播课**
- 影响力/口碑:知识性 [1-5] / 实用性 [1-5] / 学习效率 [1-5] / 情绪价值 [1-5]
- 平台分发:完播率预期 [1-5] / 点赞预期 [1-5] / 收藏预期 [1-5]
- 平台合规:总时长 ≥1h / 视频规格(16:9 / 1080p)标注 / PPT 模板适配

### 5.3 评估设计取舍

- **公开课**评估重心在"转化"(转化钩子/转化承接自然度),因为它是引流课
- **实战课**评估重心在"可复现+简历价值",因为它是技能交付课
- **录播课**评估重心在"口碑+持续收入",故用"影响力/口碑"(知识性/实用性/效率/情绪价值)替代通用流量视角,用"平台分发"(完播/点赞/收藏)替代转化;平台分发三项是事后指标,制作时以"提升它们的预期"为评估对象
- 公开课与实战课共享"标题张力/痛点戳中"两个通用流量指标,保证一套评估框架的统一性;录播课因非引流课,用"影响力/口碑"+"平台分发"替代流量视角
- "多版本差异对齐"归 phase-4 过程评估(它是同步任务),不进 phase-5 学员评估

## 6. 过程文件存储路径规范 (MANDATORY)

统一为项目根目录下 `.course/`,废弃 `_process/`(课程目录下)与 `.course-prod/` 双轨。

| 路径 | 内容 | 审计 | 保留 |
|---|---|---|---|
| `.course/{task_name}/phase-n/`(项目根) | 所有过程产物:草稿 + 各阶段正式产出(定位卡/主线/证据/同步记录/评估报告) | phase-5 审计对象取自此 | 任务结束可清理草稿,审计产出归档 |
| `courses/.../{课程目录}/` | **仅正式交付物**(大纲/讲义/PPT文稿/录制脚本/images) | — | 长期 |

**迁移与适用范围:**
- 现有实战课-3-TS 版的 `_process/` 保留为历史产物,不迁移
- 未来新课统一用 `.course/{task_name}/phase-n/`,课程目录下不再建 `_process/`
- SKILL.md 与 phases/ 中所有 `.course-prod/` 与 `_process/` 引用统一改为 `.course/{task_name}/`

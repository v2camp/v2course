# 标准交付模板

> 本模板定义 course-skill 三种核心产品（公开课、实战课、录播课）的差异化交付规范。产物体系：**公开课三产物**（大纲/讲义/课程文档）、**实战课二产物**（讲义/课程文档，**无大纲**）、**录播课五产物**（大纲/讲义/课程文档/PPT文稿/录制脚本）。多版本仅实战课；本规范只针对未来新课，现有课程不回填/不迁移。

## 1. 产品定位与交付物清单

| 产品 | 定位 | course-skill 必产交付物 | 可选交付物 | 人工产物(不审计) |
|---|---|---|---|---|
| **公开课** | 认知破题、转化承接 | `大纲.md`、`讲义.md`、`课程文档.md` | `案例卡片表.md`、`演示脚本与观测面设计.md`、`images/`、`design/` | — |
| **实战课** | 技能习得、作品沉淀 | `讲义.md`、`课程文档.md`、`images/`（**二产物，无大纲**） | 多版本(TS/Java)并行 | 案例代码仓库(外部) |
| **录播课** | 平台合作、口碑沉淀、持续收入 | `大纲.md`、`讲义.md`、`课程文档.md`、`PPT文稿.md`、`录制脚本.md` | `images/`(PPT 用图) | `录制视频.mp4`、视频剪辑、`.pptx` 成品 |

**三产物角色定位**：
- **大纲**（仅公开课/录播课）→ 运营人员：把课程结构说清楚，做流量物料用；实战课无大纲，运营依据取自讲义
- **讲义** → 讲师：备课+授课完整底稿
- **课程文档** → 学员：课后复习、自主学习的主文档，可直接当教程读

**录播课章节时长约束:** 总时长 ≥1 小时(上限 8 小时),单章节 8–20 分钟(利于完播率,严于三节课"≤30min"上限)。

**PPT文稿.md** 是 course-skill 产出的 PPT 内容稿(含每页标题/要点/讲师口播/视觉建议),人工再套三节课 PPT 模板成 `.pptx`。

**录播课价值重心:** 通过头部平台露出获得持续收入的同时,积累专业影响力(口碑)。兼顾知识性、实用性、高效率、一点点情绪价值。平台分发核心指标:完播、点赞、收藏。

## 2. 目录与文件命名规范

| 产品 | 目录命名 | 文件命名 | 风格说明 |
|---|---|---|---|
| **公开课** | `courses/公开课/`(扁平,所有讲次共目录) | `第N讲：标题（大纲）.md`、`第N讲：标题（讲义）.md`、`第N讲：标题.md`（课程文档，无前缀） | 保留中文冒号+括号风格(人可读,讲次为序);课程文档为纯标题,是主文档 |
| **实战课** | `courses/实战课/AI-Agent-实战课-N-{TS\|Java} 版/` | `标题-讲义.md`、`标题.md`（课程文档，无前缀）——**二产物，无大纲** | 连字符风格,版本后缀隔离多版本;课程文档为纯标题,是主文档 |
| **录播课** | `courses/录播课/{课程名}/`(新建) | `课程名-大纲.md`、`课程名-讲义.md`、`课程名.md`（课程文档，无前缀）、`课程名-PPT文稿.md`、`课程名-录制脚本.md` | 连字符风格,无版本后缀;课程文档为纯标题,是主文档 |

**设计取舍:** 
- 不强行统一三种产品的命名风格——公开课的"第N讲"中文序号符合其按讲次连载的现实;实战课的版本后缀是多版本管理的必需;录播课无版本、按课程名组织。
- 课程文档（面向学员的主文档）不带后缀，用纯标题命名，是该课程最"原生"的文档。大纲（仅公开课/录播课）和讲义通过后缀标识为"辅助/内部"文档。
- 学员拿到课程，看到的主文档就是 `{课程名}.md`，认知最清晰。

**实战课多版本隔离:** 多版本(TS/Java)通过目录层隔离(`AI-Agent-实战课-N-TS 版/` vs `AI-Agent-实战课-N-Java 版/`),结构骨架内部不标多版本差异。同步由 phase-4 负责。实战课二产物（讲义/课程文档）在每个版本目录下都各有一份。

## 3. 核心产物内容结构骨架

### 3.1 公开课

#### 大纲.md — 运营视角，结构清单式

```
# 第N讲: 标题
## 0. 课程信息
   - 时长 / 目标受众 / 核心价值 / 一句话主张
## 1-N. 分段结构（每段含）
   - 时间段
   - 本段目标
   - 核心内容要点（3-5条）
   - 案例/数据支撑
## 附录: 案例来源清单（每条含 URL + 摘要 + 用于哪段）
```

七大段结构必须齐全：破题段 / 核心判断段 / 公开案例段 / 焦虑拆解段 / 课程地图段 / 行动清单段 / 结论收口段

**大纲禁用**：讲师动作、演示动作、口播要点、话术提示、讲课节奏、互动设计、【敲黑板】/【知识点】等干货标注。

#### 讲义.md — 讲师视角，工程口语化

大纲展开版 + 完整口播 + 演示动作 + 干货标注 + 图（v2svg 渲染）+ 备课参考。

#### 课程文档.md — 学员视角，技术书面语

结构与讲义一致，但文体转换为客观技术文。移除讲师口语、教学提示、挖坑填坑。【备课参考】转为【延伸阅读】。【敲黑板】转为"注意"/"常见问题"。代码讲解从口播式转为注释式。

**演示脚本与观测面设计.md**(可选) — live coding 步骤 + 观测面(日志/控制台/监控)设计。

### 3.2 实战课

#### 结构骨架（Phase 1 确定，**不单独产出大纲**）

实战课为**二产物（讲义 → 课程文档），无大纲**。以下八段结构由 **Phase 1 主线结构**确定，直接作为讲义骨架：

```
# 第N讲: 标题
> 系列:{课程名}(共X课时)/ 本讲:第N课时 / 时长
## 一、系列桥接/开场破题
## 二、核心判断（一句话主张 + 错误vs正确认知表 + 本讲解决/不解决）
## 三、认知模型/原理铺垫
## 四、主案例展开（多帧拆解表:帧/关键行为/阶段/核心要点）
## 五、原理抽象（核心架构/关键代码段）
## 六、架构启示与演进路线（系列课）或 能力全景图/三域地图（单节课）
## 七、收口:行动清单
## 八、转化承接（后续课时handoff表 + 课程产品承接）
## 附录 A：深入思考题清单（仅列题干+分类，不展开）
## 附录 B：关键来源（链接+类型+发布时间）
```

> **骨架段名仅作搭结构用，不得透传成稿标题**：上面 `一、系列桥接/开场破题`、`三、认知模型/原理铺垫`、`七、收口:行动清单` 等段名是内部工作流代号，不是最终标题。成稿时每一段、每一小节的标题**必须改写为学员直白标题**——用问题句（"为什么不能把文档整个塞进向量库"）、结论句（"契约先行：Retriever 是函数类型，不是继承树"）或名词短语（"四个需要重建的判断"）。**禁止**把 `破题/收口/承接/铺垫/展开/抽象/启示` 等占位词单独立为标题，**禁止**用运营/营销修辞包装标题（如"开场钩子""带走一张速查表""送你一张 X 表"）。判定标准与正反例见 `quality-guide.md §4.7`。

#### 讲义.md — 讲师视角，工程口语化

依结构骨架展开 + 完整代码 + 图引用(images/，v2svg 渲染) + 逐行讲解 + 【备课参考】每节 2-3 篇延展阅读。

#### 课程文档.md — 学员视角，技术书面语

结构与讲义一致，文体转换为客观技术文。代码从口播式讲解转为代码+注释式。附录思考题只保留题干和追问，不给答题骨架。

### 3.3 录播课

#### 大纲.md — 运营视角，章节切片式

```
# 课程名
> 总时长 / 章节数 / 目标受众 / 合作平台
## 章节列表（每章含）
   - 序号 + 标题
   - 时长（8-20min）
   - 核心知识点（3-5条）
   - 核心案例/演示
## 章节间衔接逻辑（上一章收尾→下一章钩子）
## 附录:参考来源
```

#### 讲义.md — 讲师视角

大纲展开,每章节补:口播要点、演示动作、画面提示、【备课参考】。

#### 课程文档.md — 学员视角

结构与讲义一致，文体转换为客观技术文。移除画面提示、口播冗余。

#### PPT文稿.md — 逐页稿

```
# 课程名-PPT文稿
## 第X章 标题
### P1 标题
- 要点(bullet)
- 讲师口播
- 视觉建议(图/图表/排版)
### P2 ...
```

#### 录制脚本.md — 分镜表

```
# 课程名-录制脚本
## 第X章
| 分镜 | 画面 | 口播 | 时长 | PPT页 | 备注(出镜/屏幕操作) |
```

**设计取舍:** 公开课大纲强调"时间轴+转化段";**实战课无大纲，其结构骨架强调"认知闭环+handoff"**;录播课大纲强调"章节切片+页码/脚本交叉引用"。讲义在三种产品里都是"（大纲/结构骨架）展开版+讲师授课内容",但录播课讲义额外补"画面提示"以服务录制。课程文档在三种产品里都是"讲义去口语化后的学员主文档"。

## 4. 6 阶段按产品裁剪

phase 文件不动,差异在本表查。共享 6 阶段框架,各阶段产物按产品裁剪。

| 阶段 | 公开课 | 实战课 | 录播课 |
|---|---|---|---|
| **phase-0 探索** | 时长90min / 命名(第N讲) / 无多版本 / 破题定位 / 主案例 / 演示形态 | 时长 / 命名(版本后缀) / 多版本共性特性 / 习得定位 / 主案例 / live coding | 总时长+章节数 / 命名(课程名) / 无多版本 / 平台定位 / 主案例 / PPT+录制形态 |
| **phase-1 主线** | 破题→判断→案例→焦虑→课程地图→行动→收口 | 认知→案例→原理→全景→收口→handoff | 章节序列 + 衔接逻辑 |
| **phase-2 证据** | 公开案例证据卡 + 转化论据 | 技术案例证据卡 + 代码论据 | 知识点证据卡 + 演示论据 |
| **phase-3 生产** | 3A大纲 / 3B讲义 / 3C课程文档 (+案例卡片表 / 演示脚本) | **无 3A** / 3B讲义 / 3C课程文档 / images | 3A大纲 / 3B讲义 / 3C课程文档 / PPT文稿 / 录制脚本 / images |
| **phase-4 同步** | 跳过(无多版本);若为系列,做讲次间承接校对 + 产物结构一致性检查 | TS/Java 双版本同步 + 代码对齐记录 + 产物结构一致性检查 | PPT↔脚本↔大纲↔课程文档 四向交叉引用一致性 |
| **phase-5 评估** | 三产物分别评审(表达教练+运营专员+技术布道师) | 三产物分别评审(表达教练+运营专员+技术布道师+代码审查) | 五产物评审(三产物+PPT+录制脚本,表达教练+运营专员+技术布道师) |

**phase-4 关键差异:** 
- 实战课是唯一有"多版本同步"负担的产品；
- 录播课虽无多版本,但 PPT页码↔录制脚本分镜↔大纲章节↔课程文档 四向交叉引用需校对,作为 phase-4 录播课专属任务；
- 各课型都需做"产物结构一致性检查"——确保上游骨架（公开课/录播课为大纲，**实战课为 Phase 1 主线结构**）与各产物的章节结构 1:1 对应。

## 5. 两层评估体系

### 5.2 最终产物评估(phase-5)

**公开课**
- 流量运营(运营专员审大纲；实战课审讲义运营面):标题张力 [1-5] / 痛点戳中 [1-5] / 转化钩子合理性 [1-5] / 物料可用性 [1-5]

**实战课**
- 流量运营(运营专员审大纲):标题张力 [1-5] / 痛点戳中 [1-5] / 转化钩子合理性 [1-5] / 物料可用性 [1-5]

**录播课**

### 5.3 评估设计取舍

- **各产物各有独立评估视角**:大纲看运营价值、讲义看授课价值、课程文档看学习价值。不再用一套标准衡量不同角色的产物。
- **新增运营专员角色**:专门负责运营面的流量运营视角评估（公开课/录播课审大纲，**实战课审讲义**），替代之前由主 agent 自评的运营视角检查。
- **公开课**评估重心在"转化"(转化钩子/转化承接自然度),因为它是引流课——由运营专员审大纲来保障。
- **实战课**评估重心在"可复现+简历价值"——由课程文档的"步骤可复现性/简历价值"来衡量。
- **录播课**评估重心在"口碑+持续收入",故用"影响力/口碑"(知识性/实用性/效率/情绪价值)替代通用流量视角,用"平台分发"(完播/点赞/收藏)替代转化;平台分发三项是事后指标,制作时以"提升它们的预期"为评估对象。
- "多版本差异对齐"归 phase-4 过程评估(它是同步任务),不进 phase-5 学员评估。
- "三产物结构一致性"归 phase-4 过程检查(它是对齐任务),不进 phase-5 单产物质量评估。

## 8. 应用架构课模块划分参考（示例）

以下以「生产级电商客服 Agent 调优」系列课为例，展示应用架构课的典型模块划分方式。四个模块围绕一套完整系统，从数据到检索到对话再到工程化，层层递进，每模块独立成课，拼合后是一套完整的生产级参考架构。

### 模块一：知识供应链工程——垃圾进，垃圾出

**核心命题**：知识库质量直接决定了 RAG 系统的天花板。如何从原始文档到高质量知识切片，建立一条可观测、可量化的知识供应链？

**关键决策点**：
- 文档分级与清洗策略（哪些文档值得入库、哪些直接丢弃）
- 分片粒度与重叠策略（按语义切 vs 按固定长度切、重叠多少）
- 质量校验与坏片拦截（自动检测低质量切片、人工抽检机制）
- 元数据设计与分类标签（如何为每个切片打上可用于过滤的标签）

**量化对比项**：坏片率、Recall@20、知识库规模 vs 检索效率

### 模块二：检索引擎设计——准确率与召回率的工程权衡

**核心命题**：单路向量检索"要么漏要么噪"，如何通过多级召回架构把效果推到生产可用水平，同时兼顾延迟与成本？

**关键决策点**：
- 多路召回选型（向量 / 关键词 / 结构化过滤，三路 vs 更多）
- 融合策略（RRF vs 加权求和 vs 学习排序）
- 查询理解层（查询改写 / HyDE / 多查询扩增）
- 级联 Rerank 架构（粗排+精排，如何分配算力）
- 缓存策略（语义缓存的命中率与一致性权衡）

**量化对比项**：Recall@20、Precision@5、P95 延迟、单次检索成本

### 模块三：对话引擎与工具调用——从「问答机」到「办事员」

**核心命题**：用户要的不只是答案，而是"把事办了"。如何设计对话引擎，让 Agent 能理解意图、管理状态、调用工具、完成闭环任务？

**关键决策点**：
- 意图识别与路由（纯 LLM 路由 vs 分类器+LLM 兜底）
- 状态管理（DST 槽位填充 vs 全量上下文压缩）
- 工具调用架构（单轮工具调用 vs 多轮 ReAct vs 状态机编排）
- 工具网关（权限控制、参数校验、失败重试、降级策略）
- 多轮对话记忆（摘要记忆 vs 向量检索记忆 vs 混合方案）

**量化对比项**：任务完成率、平均对话轮次、工具调用成功率、用户满意度

### 模块四：生产级工程化与评测闭环——从「能跑」到「敢上线」

**核心命题**：Demo 能跑不代表生产可用。如何用护栏、缓存、可观测、评测体系把一套 Agent 系统推进到"敢上线、能迭代"的生产状态？

**关键决策点**：
- 五维护栏（输入/输出/工具/数据/身份安全边界）
- 三级缓存（语义缓存 / 工具结果缓存 / 提示缓存）与一致性
- 可观测体系（Token 成本、延迟、错误率、用户反馈的全链路追踪）
- 评测闭环（LLM-as-judge + 人工抽检 + CI 回归，防止效果退化）
- 灰度发布与回滚（Rainbow deployment、流量分层、效果 A/B）

**量化对比项**：Token 成本下降幅度、P95 延迟、安全拦截率、评测回归通过率、MTTR

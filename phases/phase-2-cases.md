# Phase 2 — Build the Evidence System（构建证据/案例系统）

## 目标

让案例与证据真正服务于核心主张，避免堆砌无关材料。

## 双轨并行规则

### A. 经验线（优先）

优先级如下：
1. **亲历案例/成果**（如：我带过的项目、我解决过的 Bug、我的晋升项目）
2. **观察/见闻/复盘**（如：团队发生的冲突、看到的面试题、行业内卷现状）
3. **公开案例**

经验线的用途：
- 调动受众情绪，建立代入感。
- 建立真实感，体现"我做过"或"我见过"。
- 提供叙事张力、冲突感和个人能力亮点。

允许表达：
- 可以保留模糊性以保护隐私。
- 可以侧重于过程描述。
- 辅导类：重点展示"在压力/挑战下的决策过程"。

### B. 事实线（必需但从属）

公开案例、论文、行业报告、官方文档、架构标准、财报、权威数据，主要负责：
- 支撑确定性判断。
- 限定结论边界，防止过度外推。
- 在汇报/讲义中提供可追溯的权威依据。

硬规则：
- 只要涉及**事实性判断、行业结论、架构模式、度量数据**，就必须有可靠支撑。
- 每个事实点需保留：来源名称、原始链接/出处、时间口径、在本次内容中的使用语境、风险提示。
- 辅导类：事实线应包含"职级评审标准"或"JD 核心要求"。

### B.3 演进线证据（系列实战课必需）

当 Phase 1 决定本课包含"架构演进路线图"收口段时，必须在事实线中单独采集演进证据。

#### 调研通道（强制）

工业案例调研**必须通过 agent-reach skill 执行**，禁止用通用 WebSearch 替代：
1. 先用 agent-reach 的 `web` 分类定向检索一线工程博客
   （Anthropic / Netflix / Uber / Meta / ByteDance / Google / LinkedIn / Slack 等 Engineering Blog）
2. 再用 `dev` 分类检索 GitHub 开源项目的 RFC / Architecture Decision Record
3. 必要时用 `search` 分类做补充检索（顶级会议分享、技术白皮书）

关键词策略：
- 通用模板：`{领域} architecture evolution production case study`
- 短板反推：基于本课起点档（S0）的实际失败模式，反推下一档关键词
  （例：若 S0 瓶颈是"串行执行慢" → 搜 `parallel {领域} production architecture`）

#### 采集硬约束

- **新鲜度**：案例发布/分享时间 ≤ 1.5 年（约 547 天），超期必须替换
- **真实度**：必须已在生产环境运行，非实验室 Demo、非营销软文
- **量化指标**：每个案例 ≥3 项（性能/成本/延迟/可靠性任选）
- **架构可引用**：有公开的架构拓扑图或设计文档

#### 必采字段

| 字段 | 说明 |
|:---|:---|
| 案例名 | 公司/团队 + 系统名 |
| 来源 URL | 原始链接（非二手转述） |
| 发布时间 | YYYY-MM，用于新鲜度校验 |
| 工业应用证明 | 用户规模/请求量/业务场景 |
| 量化指标 | ≥3 项 |
| 演进驱动力 | 为什么从 N 档演进到 N+1 档的真实瓶颈 |
| 使用语境 | 在本课哪个档位引用 |

#### 起点档验证

采集演进证据前，必须先确认：
- 本课主 Demo 实际实现到了 S0-S4 的哪一档？
- 禁止硬套通用模板，把已实现的形态标为"未实现"。
- 若主 Demo 已合并多档（如直接用 Plan-Execute），起点档合并记录。

## 案例/证据采集方向

- **课程类**：最有感觉、最能讲活、最能体现方法论价值的经历。
- **辅导类**：最能体现职级差、最能展示架构深度、最能回答面试官"为什么是你"的亮点成果。

## 证据使用判断表

| 用途 | 优先来源 |
|:---|:---|
| 情绪调动 / 个人亮点 / 讲述张力 | 经验线 (亲历/观察) |
| 模糊启发 / 讨论素材 | 经验线 或 事实线 |
| 确定性判断 / 架构标准 / 边界兜底 | 事实线 (公开/权威) |
| 架构演进佐证 / 工业案例 | 演进线 (agent-reach 调研, ≤1.5年) |

## 本阶段产出（必须）

- `主讲述线/经验卡`
- `事实支撑线/论据表`
- `证据分工表`（哪个负责张力，哪个负责证明）
- `证据边界说明`（哪些是个人见解，哪些是公认事实）
- `决策/架构理由卡`（若涉及关键技术选型或架构决策）
- `演进线/工业案例证据卡`（系列实战课，含新鲜度自检表）

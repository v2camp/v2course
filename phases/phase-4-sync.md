# Phase 4 — Consistency Sync（一致性对齐）

## 目标

确保演示代码、配置环境、事实论据与核心文稿之间保持 100% 一致。

## 触发条件

- 演示项目代码发生实质性变更。
- 外部依赖或技术架构调整。
- 事实论据或行业标准发生更新。
- 辅导类：目标职级标准或岗位要求发生变化。

## 对齐清单

1. [ ] **代码/演示对齐** — 文稿中所有代码示例、操作步骤、界面描述是否与实际 Demo 一致？
2. [ ] **技术逻辑对齐** — 架构图、技术选型描述是否与实际实现方案一致？
3. [ ] **论据/事实对齐** — 引用的数据、链接、发布时间是否为最新？是否有残留的过期引用？
4. [ ] **环境/配置对齐** — README、`.env.example` 等配置说明是否与实际执行环境一致？
5. [ ] **价值目标对齐** — 文稿内容是否仍服务于最初设定的价值主张，有无偏离？

## 对齐原则

- **事实优先，文稿反向适配** — 先确定 Demo 代码或行业事实的最终形态，再同步修改文档。
- **修改范围最小化** — 只修改过时或冲突的部分。
- **变更理由可记录** — 若涉及重大逻辑调整，需在 `_process/phase-4/` 记录理由。

## 本阶段产出

- 更新后的核心产物（如 `大纲.md`, `晋升汇报.md` 等）。
- `_process/phase-4/sync-record.md` 对齐记录。

## 退出条件

- 对齐清单全部勾选。
- 无过期引用残留。
- 用户确认对齐完成。

# Phase 4 — Consistency Sync（一致性对齐）

## 目标

确保演示代码、配置环境、事实论据与核心文稿之间保持 100% 一致。

## 触发条件

- 演示项目代码发生实质性变更。
- 外部依赖或技术架构调整。
- 事实论据或行业标准发生更新。
- 辅导类：目标职级标准或岗位要求发生变化。

## 对齐清单（L1-L4 分层）

### L1 产品体验层（必须对齐）
- [ ] **标题/主张对齐** — 课时标题、一句话主张、目标受众在各版本中是否一致？
- [ ] **场景/Demo对齐** — 问题场景、Demo 最终效果（学员完成后得到的作品体验）是否一致？
- [ ] **handoff 对齐** — 价值落点、后续课程衔接是否一致？

### L2 架构逻辑层（必须对齐）
- [ ] **演进档位对齐** — 演进路线的档位划分（S0-S4）是否一致？（允许合并档位但不能缺失核心阶段）
- [ ] **失败模式对齐** — 失败模式的核心问题（根因）是否一致？（表现描述可不同）
- [ ] **拓扑对齐** — 数据流拓扑（节点和边的关系）是否一致？
- [ ] **三域对齐** — 三域划分（控制流/能力/交互的分配）是否一致？

### L3 工艺规范层（必须对齐）
- [ ] **SVG 对齐** — SVG 图数量、表达的含义是否一致？（具体画法可不同）
- [ ] **标签对齐** — 干货标签（【知识点】/【要点】/【敲黑板】）位置和承载的内容是否一致？
- [ ] **排版/论据对齐** — 表格、排版、术语统一度、事实论据/数据引用是否一致？
- [ ] **附录思考题对齐** — 深入思考题数量、题型分类（架构题/深度题配比）、格式结构是否一致？（每道题的具体选题和答案深度可因技术栈特性略有差异：Java 栈选更贴合 Java 生态的题，TS 栈选更贴合 TS/Node 生态的题，但必须保证每题都通过三质量维度检查）

### L4 技术实现层（各自独立，不强制对齐）
- [ ] 类名、方法名、接口签名 → 各版本独立
- [ ] 框架选型、库依赖 → 各版本独立（写各自技术栈最地道的实现）
- [ ] 配置写法、环境变量名 → 各版本独立（只要求 .env.example 覆盖的变量一致）
- [ ] 代码行数/文件结构 → 各版本独立

> **核心原则**：学员在不同版本里学到的架构认知和工程判断力是一样的，
> 但写出的代码看起来应该像"该技术栈最地道的写法"，而不是"另一个技术栈的翻译腔"。
> 禁止为了"对齐"而做类名/方法级的 1:1 翻译式映射。

### 代码/演示对齐（通用检查项）
- [ ] **代码/演示对齐** — 文稿中所有代码示例、操作步骤、界面描述是否与实际 Demo 一致？
- [ ] **环境/配置对齐** — README、`.env.example` 等配置说明是否与实际执行环境一致？
- [ ] **论据/事实对齐** — 引用的数据、链接、发布时间是否为最新？是否有残留的过期引用？
- [ ] **演进起点对齐** — 讲义中"本课实现了什么"是否与主 Demo 代码一致？
- [ ] **跨课时 handoff 对齐** — 本课声称"下一节课讲 X"是否与下一课大纲一致？前后课演进档位是否连贯不矛盾？

## 对齐原则

- **事实优先，文稿反向适配** — 先确定 Demo 代码或行业事实的最终形态，再同步修改文档。
- **修改范围最小化** — 只修改过时或冲突的部分。
- **L4 不强行对齐** — 技术实现层差异不是"问题"，是各版本独立的正常状态。
- **变更理由可记录** — 若涉及重大逻辑调整，需在 `.course/{task_name}/phase-4/` 记录理由。

## 本阶段产出

- 更新后的核心产物（如 `大纲.md`, `晋升汇报.md` 等）。
- `.course/{task_name}/phase-4/sync-record.md` 对齐记录（按 L1-L4 分层记录）。路径规则：若有项目目录则在项目根目录下，否则在当前工作目录下。

## sync-record.md 模板

```markdown
## L1-L3 对齐项
| 对齐维度 | {版本A}位置 | {版本B}位置 | 对齐方式 |
|:---|:---|:---|:---|
| 一句话主张 | §一 | §一 | 相同 |
| P2 多源融合拓扑 | §7.3 图2 | §7.3 图2 | SVG 含义一致 |

## L4 独立实现说明
| 维度 | {版本A} | {版本B} | 差异理由 |
|:---|:---|:---|:---|
| HTTP 客户端 | fetch 原生 | RestClient | 各自生态标准 |
| 状态管理 | Annotation.Root + reducer | OverAllState + ReplaceStrategy | 框架原生机制不同 |
```

## 退出条件

- L1-L3 对齐清单全部勾选。
- L4 独立实现差异已记录（非对齐项）。
- 无过期引用残留。
- 演进起点与主 Demo 代码一致，跨课时 handoff 连贯。
- 用户确认对齐完成。

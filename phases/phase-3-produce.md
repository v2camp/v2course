# Phase 3 — Produce Core Assets（产出核心产物）

## 目标

在方向、主轴和证据系统明确后，按"大纲 → 讲义 → 课程文档"链式生产三个核心产物。每个产物只服务一个角色，确保表达风格稳定、不摇摆。

---

## 3A：产出大纲（结构层）

### 目标

把课程骨架搭清楚，运营拿到就能直接用来做流量物料。

### 输入

- Phase 1 主线结构
- Phase 2 证据卡（案例、数据、论据）

### 产出

- `大纲.md`（存入项目目录根，参与 Phase 5 审计）
- 过程产物存入 `.course/{task_name}/phase-3/3A/`

### 大纲内容规范（按课型）

#### 公开课大纲

```
# 第N讲: 标题
## 0. 课程信息
   - 时长 / 目标受众 / 核心价值 / 一句话主张
## 1-N. 分段结构（每段含）
   - 时间段
   - 本段目标
   - 核心内容要点（3-5条）
   - 案例/数据支撑
## 附录: 案例来源清单（每条含 URL + 摘要 + 用于哪段）
```

七大段结构必须齐全：破题段 / 核心判断段 / 公开案例段 / 焦虑拆解段 / 课程地图段 / 行动清单段 / 结论收口段

#### 实战课大纲

```
# 第N讲: 标题
> 系列:{课程名}(共X课时)/ 本讲:第N课时 / 时长
## 一、系列桥接/开场破题
## 二、核心判断（一句话主张 + 错误vs正确认知表 + 本讲解决/不解决）
## 三、认知模型/原理铺垫
## 四、主案例展开（多帧拆解表:帧/关键行为/阶段/核心要点）
## 五、原理抽象（核心架构/关键代码段）
## 六、架构启示与演进路线（系列课）或 能力全景图/三域地图（单节课）
## 七、收口:行动清单
## 八、转化承接（后续课时handoff表 + 课程产品承接）
## 附录 A：深入思考题清单（实战课默认4道，仅列题干+分类，不展开）
## 附录 B：关键来源（链接+类型+发布时间）
```

#### 录播课大纲

```
# 课程名
> 总时长 / 章节数 / 目标受众 / 合作平台
## 章节列表（每章含）
   - 序号 + 标题
   - 时长（8-20min）
   - 核心知识点（3-5条）
   - 核心案例/演示
## 章节间衔接逻辑（上一章收尾→下一章钩子）
## 附录:参考来源
```

### 大纲禁用内容（全部移至讲义）

大纲只讲"讲什么"和"为什么讲"，绝对不出现以下讲师专属内容：
- ❌ 讲师动作、演示动作、操作步骤
- ❌ 口播要点、话术提示、逐字稿
- ❌ 讲课节奏、互动设计、挖坑/填坑提示
- ❌ 【敲黑板】、【知识点】等干货标注（这些是讲课层面的事）

### 3A 退出门禁

- [ ] **结构完整度**：章节/分段无遗漏，逻辑连贯，与 Phase 1 主线一致
- [ ] **信息密度**：每个分段/章节有明确的核心内容要点，不是空标题
- [ ] **运营可用度**：运营拿到就能写文案、做海报、做详情页，不需要再问讲师"这节课讲什么"
- [ ] **无讲师内容残留**：大纲中没有讲师动作、口播要点等讲师专属内容

---

## 3B：产出讲义（讲师层）

### 目标

讲师拿到就能备课、上课的完整底稿。

### 前置条件

3A 大纲已通过评审（结构确认、运营可用度达标）。

### 输入

- 大纲.md
- Phase 2 完整证据（案例卡/代码论据/演进路线素材）
- （实战课）Demo 代码项目

### 产出

- `讲义.md`（存入项目目录根，参与 Phase 5 审计）
- `images/` 目录（SVG 图，存入项目目录根）
- 过程产物存入 `.course/{task_name}/phase-3/3B/`

### 讲义内容规范

结构与大纲 **1:1 对应**，但在大纲基础上增加讲师授课所需的全部内容：

| 内容维度 | 说明 |
|:---|:---|
| **完整口播内容** | 工程口语化、有张力、去 AI 腔，讲师拿着基本就能讲 |
| **演示动作/步骤** | live coding 步骤、控制台操作、界面切换提示 |
| **干货标注** | 【要点】、【知识点】、【敲黑板】承载核心干货 |
| **SVG 图引用** | 架构图、流程图、对比图，存放在 `images/` |
| **【备课参考】** | 每节末尾 2-3 篇延展阅读，附价值说明 |
| **代码讲解** | （实战课）代码片段 + 逐行讲解 + 运行效果预期 |
| **画面提示** | （录播课）每段对应画面内容、出镜/屏幕操作说明 |
| **教学钩子** | 挖坑/填坑标注（仅讲师可见的教学节奏设计） |

#### 【备课参考】规范

每节末尾必须有 **【备课参考】** 区块，格式：

```
### 【备课参考】本节延展阅读

1. **{文章标题}** — {来源/作者}，{发布时间}
   - 价值：{一句话说明为什么值得读，能补充哪个知识点}
   - 链接：{URL}

2. **{文章标题}** — {来源/作者}，{发布时间}
   - 价值：{一句话说明为什么值得读，能补充哪个知识点}
   - 链接：{URL}
```

硬性要求：
- 每节至少 2 篇
- 必须是工业界真实来源（技术博客、官方文档、论文、大厂技术分享等）
- 价值说明要具体，不能写"值得一读"这种空话
- 标注发布时间，案例新鲜度原则上 ≤2 年

### 3B 核心写作与品质标准 (MANDATORY)

进入讲义生产阶段，必须强制遵循 `references/quality-guide.md` 指南。核心硬性门禁：

#### 1. 拟真口语表达（戒除 AI 腔）
详细规范见 `references/quality-guide.md §1`。
- **绝不动用 AI 过渡词**：严格封杀"首先/其次/综上所述"等学术教科书词汇，用工程口语替代。
- **资深技术 Leader 语气**：直接、生动、一针见血，使用工程师常用黑话与大白话。
- **张力讲课公式**：每个关键技术节点以"冲突场景/深夜窒息现场"驱动，**情绪张力必须完全依据用户给出的实际案例与工程事实，禁止凭空捏造虚假场景**；案例有缺时须在撰写前与用户商讨对齐。

#### 2. 扁平化深度干货输出（戒除夸大卡片包装）
详细规范见 `references/quality-guide.md §2`。
绝对禁用角色特化卡片，以高质量、中立且深度的通用技术干货形式直接呈现，使用平实工程词汇组织内容。
一律使用 **【要点】**、**【知识点】**、**【敲黑板】** 组织并高亮干货。

#### 3. SVG 矢量图形设计（严禁 ASCII 图形）
详细规范见 `references/quality-guide.md §3`。
- 讲义中绝对禁止残留任何 ASCII 字符流程图
- 必须产出高精美 SVG 矢量图，保存为独立 `.svg` 文件存放至 `images/` 子文件夹
- 设计风格遵循现代化扁平科技感，采用三域通用配色体系

#### 4. 架构演进路线段写作规范（系列实战课）
当 Phase 1 决定本课包含"架构演进路线图"收口段时，必须遵循 `references/evolution-roadmap.md` 的四段式骨架。

#### 5. 应用架构课代码引用规范（飞书兼容）
仅适用于实战课·应用架构类型。详细规范见 `references/code-reference-feishu.md`。
- 双锚点法引用代码（类名 + 包路径简写）
- 代码片段标注路径注释
- 每讲必配核心代码索引表

#### 6. 附录深入思考题写作规范（实战课）
方法论与质量标准见 `references/interview-questions.md`。
当 Phase 1 决定本课包含"附录深入思考题"、且 Phase 2 用户已确认 4 道候选题后，在讲义末尾产出附录。

### 3B 退出门禁

- [ ] **与大纲结构 1:1 对应**：章节/分段完全对齐，不跑偏、不增删结构
- [ ] **去 AI 腔合格**：无禁用词，口语化到位
- [ ] **SVG 规范合格**：无 ASCII 图，SVG 独立存储引用正确
- [ ] **【备课参考】达标**：每节至少 2 篇，有来源有价值说明
- [ ] **干货标注规范**：【要点】【知识点】【敲黑板】使用正确，无角色卡片
- [ ] **（实战课）代码可跑通**：代码示例与 Demo 一致
- [ ] **（录播课）画面提示完整**：每段有对应画面说明
- [ ] **情绪张力有据可查**：所有痛点冲突场景基于真实案例

## 3C：产出课程文档（学员层）

### 目标

学员可以直接当教程读的技术文档。从讲义转换而来，但文体、视角、内容都做学员视角重构。

### 前置条件

3B 讲义已通过评审（内容完整、技术准确）。

### 输入

- 讲义.md
- `images/` 目录（复用）

### 产出

- `{课程名}.md`（无前缀，纯标题命名，存入项目目录根，参与 Phase 5 审计）
- 复用 `images/` 目录（不需要重新生成图片）
- 过程产物存入 `.course/{task_name}/phase-3/3C/`

### 课程文档内容转换规则

结构与讲义 **1:1 对应**，但做以下维度的转换：

| 转换维度 | 讲义（讲师视角） | 课程文档（学员视角） |
|:---|:---|:---|
| **人称** | "咱先看"、"我给大家演示一下"、"大家注意" | "本节介绍"、"以下示例展示"、"需要注意的是" |
| **干货标注** | 【敲黑板】、【知识点】、【要点】 | 保留【知识点】、【要点】；【敲黑板】转为"注意"或"常见问题"小节 |
| **讲课提示** | 演示动作、互动设计、节奏提示、操作步骤描述 | 全部移除 |
| **备课参考** | 【备课参考】（讲师读的延展阅读） | 转为【延伸阅读】（筛选后保留对学员有价值的内容） |
| **情绪张力** | 痛点冲突、窒息现场、戏剧化表达、"深夜线上事故"等 | 保留问题场景和动机，但表达方式转为客观技术描述 |
| **代码讲解** | 逐行口播式讲解、"咱来看看这行代码" | 代码+注释式讲解，精简口播冗余，保留核心逻辑说明 |
| **挖坑/填坑** | 教学钩子标注 | 全部移除 |
| **附录思考题** | 完整的答题骨架（核心思路/关键权衡/延伸方向） | 保留题干和追问，移除答题骨架（只留问题，不给参考思路） |

### 课程文档文体规范

详细规范见 `references/quality-guide.md §4`。核心原则：

1. **客观中立**：不使用第一人称复数（"我们"、"咱"），不使用直接呼语（"大家"、"同学们"）
2. **书面技术语**：表达准确、专业、流畅，不是简单地把"咱"换成"我们"
3. **可独立阅读**：不依赖讲课语境、不假设读者听过前面的课（但可以有"详见第X节"的内部引用）
4. **知识密度高**：去掉口播冗余、互动环节、重复强调，保留纯粹的知识和技术内容
5. **结构清晰**：章节标题层级分明，读者可以快速定位和检索

### 3C 退出门禁

- [ ] **与讲义结构 1:1 对应**：章节/分段完全对齐
- [ ] **去口语彻底**：无"咱"、"大家"、"我们来看"、"敲黑板"等讲师口语残留
- [ ] **去教学残留**：无演示动作、无挖坑填坑、无互动提示、无讲师侧记
- [ ] **技术表达准确**：去口语后技术含义没有偏差、没有丢失关键信息
- [ ] **可独立阅读**：不依赖讲课语境，学员直接读能理解完整逻辑
- [ ] **【延伸阅读】质量**：从备课参考中筛选后保留的内容对学员有价值
- [ ] **（实战课）代码正确**：代码片段与讲义一致，注释清晰

## 链式生产关键约束

1. **必须顺序执行**：3A 大纲评审通过后才能进 3B，3B 讲义评审通过后才能进 3C
2. **上游变更要下游同步**：大纲改了，讲义要跟着改；讲义改了，课程文档要跟着改
3. **结构一致性**：三个产物的章节/分段结构必须完全一致，方便交叉引用
4. **图片共享**：三个产物共用一套 `images/` SVG 图，不需要为课程文档单独生成

## 本阶段禁止事项

- 禁止在 Phase 0/1/2 未完成前直接产出本阶段文件。
- 禁止跳过 3A 直接写讲义，或跳过 3B 直接写课程文档。
- 禁止产出"空壳"内容（有标题无实质主张）。
- 禁止忽略 Phase 2 收集的事实支撑，凭空想象数据。
- 禁止在大纲中混入讲师专属内容（演示动作、口播要点等）。
- 禁止在课程文档中残留讲师口语或教学提示。
- 辅导类：禁止产出"纯流水账"式汇报，必须有价值提炼。
- **讲义：禁止使用任何纯学术/无情绪张力的干瘪文风，禁止遗留任何 AI 味衔接词**。
- **课程文档：禁止使用任何讲师口语、禁止保留教学钩子标注**。
- **应用架构课：禁止使用 file:// 本地文件链接，禁止缺失核心代码索引表**。

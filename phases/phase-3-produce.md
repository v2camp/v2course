## 核心写作与品质标准 (MANDATORY)

进入核心产物生产阶段，必须强制遵循 `references/quality-guide.md` 指南。以下为核心写作硬性门禁：

### 1. 拟真口语表达（戒除 AI 腔）
- **绝不动用 AI 过渡词**：严格封杀"首先/其次/综上所述/具有里程碑意义/值得注意的是"等学术教科书词汇。
- **资深技术 Leader 语气**：说话要直接、生动、一针见血。使用工程师常用黑话与大白话（如"平趟"、"踩坑"、"背锅"、"防抖"、"物理级隔离"、"生产环境秒级吞吐"）。
- **张力讲课公式**：对每个关键技术节点的引入，遵循"冲突场景/深夜窒息现场"驱动。**情绪张力调动必须完全依据用户给出的实际案例与工程事实，绝对禁止凭空捏造虚假场景。** 若案例有缺，需在撰写前与用户商讨对齐。

### 2. 扁平化深度干货输出（戒除夸大卡片包装）
绝对禁用并彻底删除任何角色特化卡片，不针对特定角色单独提示，而是以高质量、中立且深度的通用技术干货形式直接呈现。一律使用平实工程词汇组织内容（详见 `references/quality-guide.md`）：
- **禁用卡片组件**：严禁使用 `💡 [讲师侧记]`、`⚠️ [学员踩坑警告]`、`🎯 [面试突围金句]` 等包装框。
- **中立词汇组织**：一律使用 **【要点】**、**【知识点】**、**【敲黑板】** 组织并高亮干货。
- **严禁浮夸绝对词汇**：严禁使用"闭眼背诵"、"职级差回答"、"神级话术"、"降维打击"等针对特定角色的浮夸或绝对化暗示词，专注客观深度和工程实践本质。

### 3. SVG 矢量图形设计（严禁 ASCII 图形）
- **绝对隔离**：讲义中绝对禁止残留任何 ASCII 字符流程图（如 `┌─┐` 或 `-->`）。
- **独立 SVG**：必须针对流程、架构、对比画出高精美的 SVG 矢量图，保存为独立 `.svg` 文件存放至对应课程目录下的 `images/` 子文件夹。
- **规范设计**：设计风格遵循现代化扁平科技感，采用三域通用配色体系（控制流域紫色系、能力域绿色系、交互域蓝色系），并使用标准的 Markdown 语法进行相对路径引用。

### 4. 架构演进路线段写作规范（系列实战课）
当 Phase 1 决定本课包含"架构演进路线图"收口段时，必须遵循 `references/evolution-roadmap.md` 的四段式骨架，约 10 分钟：

**X.1 当前坐标（2min）**：
- 【知识点】三域地图，定位本课实现的架构在三域中覆盖了什么
- 表格：手写实现 vs 框架实现的三域映射
- 与前序课程的能力进阶对照
- 收束句：这只是演进的起点

**X.2 为什么只是起点（2min）**：
- 3 类失败模式表格（表现 / 根因 / 由哪档解决），失败模式必须基于本课主 Demo 实际短板推导
- 【敲黑板】：架构瓶颈，调参解决不了

**X.3 演进路线图（5min）**：
按 S0→S4 顺序（起点档可合并），每档包含：
- SVG 架构图引用（每档至少 1 张，总图 evolution-roadmap.svg 必有）
- 核心变化（一句话）
- 解决什么（对应 X.2 哪个失败模式）
- 工业案例佐证（≤1.5 年，附来源链接 + 发布时间 + 量化指标）
- 关键工程要点（3-4 条可复用经验）
- 本质金句（一句话收束本档）
- 【敲黑板】（仅关键档位，标出代价/边界，如多 Worker 并行的 Token/资源成本）

**X.4 收口矩阵（1min）**：
- 三域 × 各档位演进矩阵表格
- 一句话定位本课落点
- 后续课程 handoff（下节课落地哪一档）

硬性规则：
- 起点档必须 = 本课主 Demo 实际实现的架构（严禁硬套通用模板）
- 每档工业案例必须标注来源 + 发布时间 + 量化数据出处
- SVG 总图必出（evolution-roadmap.svg），档位图按需出
- 引用外部企业架构图必须附 attribution（公司名 + 博客标题 + URL）

# Phase 5 — Review & Finalize（综合评估与定稿）

> **审查前置（MANDATORY）**：本阶段启动前，先按 `SKILL.md §2 课型矩阵` 加载该课型的**完整必载 reference 清单**，再按 `references/review-checklist.md` 九维总表逐维勾稽。补齐这一前置，是为了修复"审查时只按单文档（如 quality-guide）做文体润色、漏掉量纲/演进/引用/双端/代码等其它必载维度（如 architecture-course 的量纲纪律 90/150）"的既往缺口——审查必须多维度准确落地，不单看文体。

**Step 0 机械闸门（开审前必跑）**：`node scripts/course-lint.mjs scan <目录>` → `structure <目录>` → `kiss <目录>`。scan 有命中先清零（禁词 / ASCII 组图含目录树 / 占位标题 / 图片可达 / 内嵌 / 围栏成对）；structure 的 ❌ 段数不一致必须解释（🟡 仅措辞差异可留）；kiss 只出量化报告，供判定段落体量。**脚本判不了语义**——人接着做 `review-checklist.md` 审查总原则 0 的「关键分析结构清单」，再逐维勾稽。

**Step 0.5 定位核对（1 分钟，MANDATORY）**：用 `phases/phase-1-spine.md` 的六问对照产物首段——主张 / 受众 / 痛点 / 边界 / 叙事 / Impact 与成稿是否一致。六问即 TAPS 的落地，这一步只做**兑现核对**（首段承诺的每件事在正文找到对应段落），不重新设计定位；不一致标 🔴 回 Phase 1。

## 目标

通过多视角评估及专家独立审查，确保**本课型各核心产物**（公开课：大纲/讲义/课程文档；**实战课：讲义/课程文档，无大纲**；录播课另含 PPT文稿/录制脚本）各自的角色边界清晰、表达风格稳定、内容质量达标，达到卓越品质标准。

## 2. 视角 A-I 综合评估 (MANDATORY)

在专家审查前，主 Agent 必须完成以下自我评估。如果某项不合规，必须返回对应 Phase 3 子阶段修正。

### 视角 A：流量运营与转化视角（公开课/录播课对应大纲；**实战课对应讲义**）

- **吸睛度与张力**：各分段/章节标题是否在 10 秒内能抓住注意力？痛点引入是否有强烈的冲突感？
- **转换/桥接**：课程地图/handoff 段是否清晰且有吸引力？本课如何与后续课时无缝桥接？
- **物料可用性**：运营拿到大纲（公开课/录播课）或讲义（实战课），能不能直接产出详情页、海报、推文要点？不需要再追问讲师"这节课讲什么"？

### 视角 B：讲师授课视角（对应讲义）

- **口语化质量**：去 AI 腔是否彻底？语气是否像资深技术 Leader 面对面授课？
- **活人感（`human-prose.md` §3–5）**：材料是否可指认；换一个模型也能原样写的段落有多少；每段是否新增；翻案腔/假具体/假深刻是否清零；主干与指接是否顺畅。
- **授课完备性**：演示动作、节奏提示、备课参考是否齐全？讲师拿着能不能直接备课上课？
- **张力与叙事**：痛点冲突是否到位？是否严格基于真实案例？
- **密度评估**：内容量是否匹配预设课程时长？

### 视角 C：学员学习视角（对应课程文档）

- **可读性**：学员直接读能不能看懂？是否需要依赖讲课语境？
- **知识密度**：内容是否精炼？有没有口播冗余或教学残留？
- **难度匹配**：内容难度是否适合目标学员水平？
- **可复现性**：代码步骤是否清晰？跟着做能不能跑通？

### 视角 D：深度技术架构（讲义 + 课程文档）

- **技术深度与本质**：是否正确使用【知识点】承载和挖掘深度的底层原理、设计思想？这些内容是否具有架构师级的深度与洞察力？
- **无夸大包装**：是否清除了所有浮夸的角色特定修饰语？
- **两文档一致性**：讲义和课程文档的技术内容是否完全对齐？有没有因为文体转换导致技术偏差？

### 视角 E：演进路线专项（系列实战课必检）

- **案例新鲜度**：工业案例发布时间是否 ≤1.5 年？是否填写了新鲜度自检表？
- **起点对齐**：讲义中"起点档"描述是否与主 Demo 代码实际实现一致？
- **图完整性（演进路线专项）**：演进路线总图（evolution-roadmap.svg）是否存在？每档是否至少 1 张图且由 v2svg 渲染、引用路径正确、回执通过？
- **数据溯源**：所有量化指标是否标注了来源（公司 + eval 规模 + 时间）？
- **跨课时连贯**：handoff 到下一课的内容是否与下一课大纲一致？前后档位不矛盾？
- **失败模式真实性**：3 类失败模式是否基于本课主 Demo 实际短板，而非套模板？

### 视角 F：附录深入思考题专项（实战课必检）

F1-F10 判据唯一定义见 `references/interview-questions.md` §2/§7，本段只列编号、不复述判据。对附录中每道题逐条核对：
- F1 知识结构
- F2 紧扣超纲
- F3 trade-off
- F4 追问链
- F5 答题骨架
- F6 关联阅读
- F7 非基础题
- F8 题型配比
- F9 篇幅控制
- F10 不给完整答案

### 视角 G：代码引用与飞书兼容专项（应用架构课必检）

仅实战课·应用架构类型需要检查，基础/实战课跳过此视角。G1-G10 判据唯一定义见 `references/code-reference-feishu.md` §8，本段只列编号、不复述判据。逐条核对（讲义和课程文档都要检查）：
- G1 零 file:// 链接
- G2 类名行内代码格式
- G3 首次出现带路径
- G4 包路径简写无歧义
- G5 核心代码索引表存在
- G6 索引表完整性
- G7 索引表准确性
- G8 系列首讲有前置说明
- G9 代码片段带路径注释
- G10 无过度代码搬运

### 视角 H：教学代码生产级门禁专项（实战课必检）

仅实战课·基础/实战、实战课·应用架构需要检查。H1-H8 判据唯一定义见 `references/multi-track-production.md` §2（编号已写入 §2.1-2.4），本段只列编号、不复述判据。教学代码是学员的**可复现交付物**，审查不能停留在文档级静态视角，必须上升到"能真实跑"。逐条核对：

- H1 可编译可运行
- H2 可复现运行环境
- H3 评测指标基线对照
- H4 回退红线
- H5 量化数字实测后写入

**应用架构课额外必检（工业落地验收）**——应用架构课代码以**工业项目落地标准**驱动而非仅为演示，以下三者必须同时满足方可作为课程交付形态：

- H6 主要用户动线端到端跑通
- H7 无明显体验问题
- H8 禁止双轨验收

> 与代码质量的区分：代码质量视角（代码审查专家）查"代码本身写得好坏"（静态、P0/P1）；本视角查"能否真实跑 + 评测指标有章可循"（运行态、生产级交付形态）。两者互补，都要过。

### 视角 I：讲义内容可执行性专项（含代码与命令的课型必检）

视角 H 管的是**仓库代码**能不能跑；本视角管**讲义里写的命令、自检断言、代码块、数字、标题承诺**能不能兑现。规范定义见 `references/executable-claims.md`。逐条检查（讲义与课程文档都要查）：

- **I1 命令可跑通**：命令走仓库正式入口（`scripts/run-eval.sh`、`pnpm --filter X start` 等），不绕过 `.env` 装载、构建前置与陈旧制品门禁；手搓等价物必须写明"绕过了什么"。
- **I2 断言与命令分支同源**：带 `--fallback`／`--force`／`--mock` 等开关时，断言串必须等于该分支的实际返回值（同一命令不同开关走不同分支）。
- **I3 代码块可编译**：标「现场写」的块签名齐全、抽象方法全实现、被调私有方法可见；节选或注释占位必须显式标注省略了什么，且块后的"跑一下"与补全程度相符。
- **I4 数字与当前代码/口径一致**：横比代码常量与单测实际输出，纵比口径文件（先看有无"已过期/不得引用"标记，再看数值）；双轨同指标必须同值，双口径必须写明分母。
- **I5 标题承诺有对应正文**：标题里的动作或结论在正文有段落兑现；兑现不了就改标题，不为保标题硬加内容。

## 3. 审查角色与分工

| Subagent | 审查对象 | 审查维度 | 不审查 |
|:---|:---|:---|:---|
| **表达教练** | 本课型全部产物（公开课含大纲；实战课为讲义+课程文档） | 各产物的表达风格、结构质量、排版规范、图形合规（v2svg 回执：composition 全过、theme_readable、caption_present） | 详细技术细节、具体代码语法 |
| **技术布道师** | 讲义 + 课程文档 +（代码引用） | 技术准确性、代码可运行性、配置一致性、两文档技术一致性、代码引用准确性 | 叙事、案例叙述、价值表达、去 AI 味 |
| **代码审查专家** | 代码项目 | 代码本身的技术质量（按本次声明的技术栈审查） | 讲义内容、课程设计、表达风格 |
| **运营专员** | 大纲（公开课/录播课）；**讲义（实战课）** | 标题吸引力、痛点清晰度、转化钩子、物料可用性 | 技术内容、讲师表达、代码质量 |

> **技术布道师 vs 代码审查专家的区别**：
> - 技术布道师 = "讲义/课程文档里写的代码和实际代码对不对得上"（文档侧）
> - 代码审查专家 = "代码本身写得好不好、有没有 bug、架构合不合理"（代码侧）
> - 两者互补，缺一不可

> **G1-G10 执行口径**：代码引用与飞书兼容专项（G）由**技术布道师一人负责全部十条**（含格式类与准确性类，判据见 `references/code-reference-feishu.md` §8），不拆分给表达教练；表达教练的通用排版规范职责不含 G 条目。

## 4. 执行步骤

### Step 1：主 Agent 专项质量自评

按产物分别进行自评，产出 `.course/{task_name}/phase-5/evaluation-summary.md`：

**大纲自评重点**（仅公开课/录播课；实战课无大纲，运营面自评并入讲义）：
- 结构完整度（章节/分段无遗漏）
- 信息密度（每段有核心要点，不是空标题）
- 无讲师内容残留（没有演示动作、口播要点等）
- 运营可用度（运营拿到能不能直接用）

**讲义自评重点**：
- 是否存在禁用词（首先/其次/综上所述等）？
- **情绪张力是否绝对基于真实案例？（严禁凭空捏造）**
- **是否彻底清除了三大卡片组件与浮夸词汇？**
- **是否规范使用【要点】、【知识点】、【敲黑板】承载核心干货？**
- 是否无 ASCII 图，且 v2svg 回执通过、引用路径正确？
- 【备课参考】是否每节至少 2 篇，有来源有价值说明？
- **演进路线案例新鲜度是否 ≤1.5 年？起点档是否与主 Demo 代码一致？**
- **附录深入思考题是否通过 F1-F10 全部检查项？（若本课包含附录）**
- **（应用架构课）代码引用与飞书兼容性是否通过 G1-G10 全部检查项？**
- **（实战课）教学代码生产级门禁是否逐条通过 `multi-track-production.md` §2（2.1 可编译可运行 / 2.2 评测基线与回退红线 / 2.3 量化实测 / **2.5 代码对照与接线核验**；应用架构课另加 2.4 工业落地验收）？**

**课程文档自评重点**：
- 去口语彻底性（无"咱"、"大家"、"我们来看"等）
- 去教学残留（无演示动作、无挖坑填坑、无互动提示）
- **去时间标记（基础/实战/公开课必检）** — 章节标题中不得残留 `（15min）` 等地段时长标记；讲义可保留，课程文档必须剔除（见 Phase 4 时间标记拉齐检查项）
- 技术书面语质量（表达准确、专业、流畅）
- 可独立阅读（不依赖讲课语境）
- 与讲义技术内容一致性
- 【延伸阅读】质量
- **（应用架构课）代码引用与飞书兼容性是否通过 G1-G10 全部检查项？**

### Step 2：并行启动专家审查

启动表达教练、技术布道师、代码审查专家、运营专员 subagents，分析产出：
- `.course/{task_name}/phase-5/expression-review-report.md`（表达教练，含各产物分别审查）
- `.course/{task_name}/phase-5/tech-review-report.md`（技术布道师，含讲义+课程文档）
- `.course/{task_name}/phase-5/code-review-report.md`（代码审查专家，若有代码）
- `.course/{task_name}/phase-5/operation-review-report.md`（运营专员；公开课/录播课审大纲，**实战课审讲义**）

**应用架构课额外要求**：
- 技术布道师报告必须包含「代码引用准确性与飞书兼容性」专项检查结果（G1-G10 全十条，讲义和课程文档都要查）

### Step 3：汇总与改进

- 如果自评或任何专家报告显示"不合格"或存在 🔴 项，必须返回对应 Phase 3 子阶段进行改进。
- **批量返修**（一次修 ≥5 条，如批量审查已完成课程、跨课统一、双轨对齐）按 `references/repair-discipline.md` 执行：R1 核实先于修改（审查断言未回读代码/口径文件不得直接改）、R2 逐条对齐原文（定位不到就跳过记录）、R3 禁止清单（结构分叉／骨架替换／口径分叉／需改代码四类不得由文档侧单方面修，须升级为决策项）、R4 双端同步矩阵、R5 代码块只从源文件复制、R6 改动面控制（P2 不动、审查与修复分离）。
- 修完必须回归：`course-lint scan` 归零 + `structure` 段数一致 + 抽检每类问题各 1 条。
- 大纲问题 → 返回 3A（仅公开课/录播课；实战课无大纲）
- 讲义问题 → 返回 3B
- 课程文档问题 → 返回 3C
- 上游修改后，下游产物要同步更新

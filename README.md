# Course Skill

这是一个高级课程产品制作 Skill。它旨在指导从 0 到 1 策划并制作高品质的各类课程与辅导材料（包括公开课、实战课、录播课、迷你课、晋升/面试辅导等），支持多版本管理与多视角评估。录播课:与三节课等平台合作的线上课,1–8 小时、8–20 分钟章节;course-skill 管到脚本层(选题/大纲/讲义/PPT文稿/录制脚本),视频录制/剪辑留给人。

## 🌟 核心能力

- **Plan 驱动工作流**：强制进入计划模式，6 阶段产出流程（探索→主轴→证据→生产→同步→审查）。
- **多课程类型支持**：完整支持公开课、实战课·基础/实战、实战课·应用架构、迷你课、晋升/面试辅导、录播课等多种课程类型。
- **实战课·应用架构专项方法论**：针对"基于已有生产级代码分模块讲解架构演进"的课型，提供子系统演进叙事法、ADR轻量决策讲解、代码引用零容错、量化指标驱动、评测闭环等专项支持（详见 `references/architecture-course.md`）。
- **架构演进路线**：系列实战课支持"架构启示与演进路线图"收口段，基于工业案例（≤1.5年新鲜度）构建 S0-S4 从原型到生产的演进路径。
- **附录深入思考题**：实战课每讲末尾附 4 道思考题（3 架构题 + 1 深度题），从本课架构向上推演，附答题骨架+工业界关联阅读，启发架构思维而非背八股。候选题 8-10 张 → 人工选 4 道。
- **多版本 L1-L4 分层同步**：产品体验/架构逻辑/工艺规范三层必须对齐，技术实现层各自独立（不做类名级翻译映射）。
- **领域无关工艺**：核心工艺流程是领域无关的，任意技术领域均可通过 `references/domain-adaptation.md` 在 Phase 0 声明技术栈、三域映射、S0-S4演进档位映射后使用。
- **联网研究专业化**：Phase 2 工业案例调研与深入思考题候选题检索强制通过 agent-reach skill 执行，保证案例质量与新鲜度。
- **企业级排版规范**：内置飞书等协作平台的 Markdown 兼容性规范（表格对齐、特殊修饰符隔离）。
- **视觉资产升级**：强制将传统的 ASCII 文本图形升级为高质量的 SVG 矢量图，三域通用配色（控制流紫/能力绿/交互蓝）。
- **去 AI 腔与拟真口语**：内置表达教练与技术布道师子 Agent，强制规避 AI 常用套话，使用资深工程师的工程口语。
- **代码质量把关**：内置代码审查专家子 Agent，技术栈自适应（按 Phase 0 声明的技术栈应用对应审查规则）。
- **六视角质量门禁**：产出后必须经过"流量运营视角"、"最终学员视角"、"代码质量视角"+"演进路线专项"+"深入思考题专项"+ **"应用架构课专项审查"**（代码引用准确性/量化数据真实性/演进叙事合理性/反过度设计）的严格审计。

## 🚀 如何使用

在支持 Agent Skill 的 IDE（如 Trae）中，当用户意图涉及"写讲义"、"做大纲"、"课程策划"时，Agent 会自动触发此 Skill。

你也可以通过显式指令调用：
```text
Use Skill: course-skill 帮我为《XX实战课》写一份大纲
```

### Skill 依赖
- **agent-reach**：Phase 2 工业案例调研与深入思考题候选题检索必须通过 agent-reach skill 执行联网研究。

## 🛠️ 核心规范速览

### 通用规范
1. **过程文件隔离**：所有过程产物必须存放在项目根目录的 `.course/` 下，禁止污染正式课程目录;课程目录只放正式交付物。
2. **SVG 绝对隔离**：严禁在 Markdown 内部嵌入 SVG 代码，必须存入 `images/` 目录并使用相对路径引用。
3. **禁用角色卡片**：严禁使用 `[讲师侧记]`、`[学员踩坑警告]` 等包装卡片，一律使用平实的 **【要点】**、**【敲黑板】**、**【知识点】** 承载干货。
4. **L1-L4 分层同步**：多版本只对齐产品体验(L1)/架构逻辑(L2)/工艺规范(L3)，技术实现(L4)各自独立写地道代码。
5. **工业案例新鲜度**：演进路线引用的工业案例必须 ≤1.5 年，必须有量化指标和来源标注。
6. **附录深入思考题**：实战课默认 4 道（3 架构 + 1 深度），必须通过"知识结构/紧扣超纲/trade-off"三质量维度，候选题经人工确认后写入附录，只给答题骨架不给标准答案。

### 实战课·应用架构专项规范
7. **代码先行**：必须等代码开发完成、评测指标达标后才能开始写讲义，禁止先写稿再补代码。
8. **代码引用零容错**：引用类名/方法名/路径前必须Read真实文件，禁止凭记忆/设计稿虚构，代码片段必须是真实可运行代码。
9. **演进叙事**：每个模块按"Baseline问题→优化1（问题+量化收益+trade-off）→优化2→...→最终方案"的阶梯式讲解，不直接展示完美方案。
10. **量化驱动**：每节课必须有指标对比表（Baseline→各阶段→最终），数据必须可通过评测脚本复现。
11. **架构决策透明**：关键决策必须讲Context/Options/Decision/Consequences，必须讲"什么时候不需要这个设计"，避免过度设计。
12. **讲决策不讲代码**：应用架构课讲子系统级架构决策和trade-off，不逐行读代码；代码片段只选10-30行核心逻辑，完整代码让学员去仓库看。
